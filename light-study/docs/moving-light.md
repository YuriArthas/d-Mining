# 街道移动提灯

公开入口：<https://w-sunjun-public.dev.clock-p.com/games/mining-light/index.html>。

此前是按需实时渲染：拖动相机、切换日夜或配置时重画，静止时不提交新帧。原来的三盏固定灯使用静态可见性缓存。现在默认增加一盏暖色提灯，运动期间持续提交实时画面；路面、墙面照明和物体投影随其位置变化。

## 操作与运动

- 左下角“暂停 / 继续”冻结或恢复灯的位置；“关闭 / 开启”移除或恢复这盏灯。暂停和关闭时恢复按需渲染，相机仍能操作。
- 提灯距路面约一米，沿街道 `z=7 ↔ -13` 往返，完整周期 32 秒。余弦路径在两端自然减速；运动按经过的秒数计算，不按帧计步。
- `?motion=paused` 可直接打开暂停状态，`?motion=off` 可对照原街景。隐藏标签页时停止请求新帧，返回时重置时间锚点，避免把后台等待计入位移。
- 调试入口 `__lightStudy.motion(mode)`、`motionTime(seconds)` 和 `draw()` 支持固定灯位与同机比较；固定时间会自动暂停。

## 渲染和成本

当前默认采用独立动态阴影通道：真实 PointLight 和六面 1024² 阴影保留，0.22 m 发光半径及 9 m 光程不变；软阴影过滤在独立缓冲计算，按深度/法线重构后供主材质读取。常驻分块投影几何减少阴影提交，未减面或改变可见街景。原 24/48 次 PCSS 仍可用 `?dynamicShadow=pcss` 对照。

运动时持续渲染，最多两帧在途；CPU 不再等 GPU 完成才请求下一帧。完成计时与 GPU 查询仍绑定各自帧。暂停和关闭后回到按需渲染。固定灯继续使用静态可见性缓存。

用户指定的实机目标为 GPU 中位数 ≤3 ms、P95 ≤5 ms。新架构、自动对照协议和验证证据见 [dynamic-light-optimization.md](dynamic-light-optimization.md)。目标尚需新构建的 iPhone 报告验收，软件浏览器数据不能当作 Apple GPU 结果。

## 准备、资产与上报

- 开放交互前，以当前日夜/AO/灯配置准备完整驻留场景的实际渲染图。暂时关闭视锥剔除，等待 shader / pipeline 数量与阴影稳定后恢复剔除，最多六帧；失败明确报错。只准备当前配置，不声称预热全部日夜、灯开关或诊断变体。`warmup` 单独记录准备帧数、管线/program 创建数与耗时。
- 这是对 `5450a143` 报告中首次可见灯笼现场创建管线的针对性处理。首轮公开检查准备三帧；进入交互后的前五帧没有新建管线/program，原长帧相机位置重放亦无新建。仍需实机报告确认 CPU 和 GPU 耗时。
- 提灯是新 Blender 模型，524 三角面，无纹理。源文件 `source-art/moving-lantern.blend`，生成脚本 `tools/blender/build_moving_lantern.py`；尺寸和三份 SHA256 记录在 `artifacts/moving-lantern-asset.json`。没有复用旧模型、减面或伪造 Tripo ID。
- 原街景 GLB、布局、材质与固定灯配置未改变。历史阴影烘焙分支在创建移动灯前返回，未宣称重新烘焙。
- 上报升级为 schema 3，保留最近最多 1800 帧，每帧记录灯位、时间与 moving / paused / off 状态。动画帧标为 `animation`；灯的每个位置不另建统计组。一次点击即可在连续动画中补采并上传历史，包含动态阴影通道成本。导出截止本次补采帧，不混入其后尚在运行的帧。

## 原移动灯版本的公开验证

首轮构建 `street-BUqsKPUj.js` 已验证默认连续运动、暂停、恢复、关闭、动画中上报落盘内容一致、动态六面阴影和固定灯缓存。固定 `t=0/8/16` 的公开截图显示暖光与遮挡阴影随位置移动；关闭提灯后的 1440×900 场景与前版逐像素一致。

最终构建 `street-BEst4ygv.js` 追加验证了暂停状态下延迟 GPU 读回后的上报、日夜切换、恢复/暂停/关闭以及关闭 GPU 计时后的动画上报，均通过且无浏览器错误或警告。完整记录见 `artifacts/moving-light/verification.json`，首轮记录在 `public-check.json`，最终针对性检查在 `final-check.json`。所有浏览器检查均在发布后访问公开 URL；T3 预览返回主机 AppArmor 不支持，使用项目既有 Playwright / Vulkan SwiftShader 流程。
