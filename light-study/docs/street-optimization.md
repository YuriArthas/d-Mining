# L12：保留光感的街景渲染优化

范围是独立公开街景 `mining-light`。按已安装的 CloudAI-X Three.js 技能中的性能测量、WebGPU shader 和后处理方法，核对实际 r186 源码与公开生成的 WGSL。未改动游戏本体或资产造型。

## 交付实现

- `streetEnvironment.ts` 将 r186 PMREM/CubeUV 查找专门化为当前两张天空贴图的固定布局。相邻粗糙度层共享一次立方体面投影；漫反射的固定粗糙度 1 使用固定层。保留原始 PMREM 纹理、粗糙度映射、面 UV 约定、线性插值、环境旋转、法线与反射向量、颜色及强度，不改用近似常量环境光。显式 WGSL 函数通过 `three/tsl` 接入，未重复导入另一套 Three Node 系统。
- AO 专用法线/深度通道采用单采样；最终照明和发光输出保持全分辨率、RGBA16F 和 4× MSAA。AO 半分辨率、12 个采样、半径与强度原样保留。它是辅助缓冲的调整，需用图像对照确认边缘影响。
- 白天将强度为零的三盏点灯从渲染灯列表中移出，生成只含太阳的着色器变体；夜晚恢复。灯具模型、灯罩和窗口发光没有隐藏。两套天空继续预生成并复用，切换不重做 PMREM。
- 默认启用优化；`?render=reference` 保留本轮前的渲染方式，`?render=optimized` 显式选择新方式。性能栏显示当前方式。静态遮挡制作入口始终走 reference，保留原制作条件。

模型、布局、材质、静态柔影图集和 PCSS 参数未变。普通物体没有按距离卸载，主画面没有缩小或关闭抗锯齿。

## 诊断及撤回的方案

以公开入口、1440×900 / DPR1、相同街口机位测量。`probe-no-msaa` 主通道约 4932 ms，`probe-single-output` 约 6947 ms，`probe-no-environment` 约 4777 ms；同期原路径约 7268 ms。前两项分别关闭主 MSAA、移除发光附件及光晕，后一项移除环境光，**仅用于归因，均不作为交付画面**。数据为 SwiftShader 软件 GPU，不是用户笔记本耗时。

- 点灯范围/零贡献提前退出：首版有 TSL 共享临时变量跨分支错误，第三盏灯缺光。修正图集采样作用域后，街口逐像素一致，但软件 GPU 没有稳定收益；已移出运行时代码。修正后的试验源与证据保留在 `range-r2/`。
- 环境 shader 第一版因 WGSL 保留字 `filter` 编译失败，已修复并重新发布验证；失败记录保留在 `environment-r1/`。
- 首次多页面诊断浏览器在第二个变体期间关闭，`probes/report.json` 标明未完成；不能把空样本当结果。最终各变体使用独立浏览器进程，顺序运行，避免遗留设备资源互相影响。
- 单独环境改写的 `environment-r2` 街口与原版逐像素一致；单独加入单采样法线的 `normals-r1` 最大通道差 1/255。这些是中间试验，最终验收以 `final/` 为准。

## 复现

先发布，再运行公开检查：

```sh
npm --prefix light-study run publish
VARIANTS=reference,optimized SAMPLES=3 node light-study/tools/check-street-optimization.cjs
python3 light-study/tools/verify-street-optimization.py
```

`check-street-optimization.cjs` 记录公开 JS 哈希、实际 GPU 时间戳、缓冲采样数、材质/灯状态、三机位日夜截图、日夜与 AO 恢复、空闲停止提交、resize、实际指针拖动及 WGSL 编译信息。`verify-street-optimization.py` 比较图像、恢复状态、资产/范围哈希及构建对应关系。

最终证据目录：`artifacts/lighting-optimization/final/`。旧缓存来源仍以原 bake 依赖哈希为准；`street-shadow-asset.json` 的 `runtimeCompatibility` 引用原始源码存档和当前运行时代码哈希，记录为何本次改动不改变制作输入，不冒充重新制作过图集。

## 最终公开桌面结果

发布模块为 `street-DTfU7pZ9.js`。公开响应、截图执行所用 JS 与本机构建的哈希已核对；39 个原资源、680 个范围外工作区文件、1,116 个其他游戏发布文件保持不变。

同一主机 SwiftShader、1440×900 / DPR1、街口夜景，各预热后采集三个独立暖帧；两版均为 117,156 三角面、19 个常驻批次、48 draws / 8 passes：

| 路径 | 三帧总 GPU ms | 总中位数 ms | 主照明中位数 ms | 法线通道中位数 ms |
| --- | --- | ---: | ---: | ---: |
| Reference | 8123.09 / 8119.18 / 8115.02 | 8119.18 | 7269.04 | 406.05 |
| Optimized | 6472.60 / 6513.61 / 6466.15 | 6472.60 | 5905.92 | 105.80 |

软件总成本下降 **20.28%**。白天分别记录到 7598.49 / 4782.95 ms 的单个暖帧，仅作诊断，不作为统计基准。Three 内存估计约 244.6 / 244.5 MiB，不能用它声称实际驱动显存大幅下降；它没有完整反映后端多采样附件。

- 原路径街口与改动前留档逐像素一致；关 AO 的新旧夜景逐像素一致。
- 夜景三机位平均通道差 0.0040–0.0053 /255，最大 2/255；柔影、发光和材质响应保留。
- 白天三机位平均通道差 0.0578–0.0615 /255，最大 7–9/255；差异集中于 AO 的接触边缘，通道差大于 3 的像素不超过 0.063%。这是辅助缓冲采样改变造成的细小画面差异，不能称整体逐像素等价。已查看原图与放大差分。
- `day-normal-control` 使用原照明路径配合相同单采样 AO；白天街口与优化版逐像素一致，隔离证明可见微差来自 AO 辅助缓冲。`live-final` 的实时 PCSS 街口与历史原路径最大差 1/255，软/硬开关确实改变画面，两种模式无页面/WGSL 错误。补充核对见 `final/supplemental-verification.json`。
- 昼夜、AO 开关、鼠标拖动及 resize 之后回到原视图，截图逐像素恢复。性能栏、1280×800 缩放、空闲停止提交均通过。
- 完成的公开检查没有页面或 WGSL 错误/警告；构建、来源校验、图像/范围验证均通过。
- 首次完整检查在优化版切换机位时浏览器退出，无页面/WGSL 错误。保留 `final/attempt-1.json`，优化版在独立浏览器完整重跑通过；`final/report.json` 合并首轮已完成的 reference 与重跑的 optimized，二者执行的 bundle 哈希相同。重跑前后宿主 OOM 计数未增，未查明首次退出原因，不将其归因于已证明的 OOM 或代码错误。

## 验证边界

本机无物理 GPU，SwiftShader 只用于功能、画面和软件执行成本对照。T3 预览浏览器明确报告宿主 AppArmor 不支持，故使用项目原有 Playwright 公开 URL 流程。实际笔记本 2406×1309 / lovelace 的收益尚未获得新测量，不能由软件百分比推算。

本轮优化当前三灯街景；尚未实现 12/30 灯空间列表、动态角色遮挡或大场景压力验收，不能宣称多灯架构问题已解决。继续扩建前仍需依据 `lighting-architecture-review.md` 验证灯光列表与静态/动态遮挡的接合。
