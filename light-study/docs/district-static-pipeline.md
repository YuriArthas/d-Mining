# 静态街区 GPU 管线优化

本页记录 L27 的三通道实现及 L28 实机结果。后续 L29 已改为半分辨率双向光晕、修复 Node 入口混用，并增加分项对照，当前实现见 [district-cost-probes.md](district-cost-probes.md)。

用户目标仍为同一 iPhone、相同条件下 GPU 中位数 ≤3 ms、P95 ≤5 ms。旧报告 457825ad 的夜间巡游为 12.268 / 13.818 ms，提交帧率 60 FPS 不能证明 GPU 余量达标。

## 最终实现

保留 642,264 三角面、材质/PBR/法线图、天空与环境高光、4× MSAA、4096² 灯光图、静态灯和持续渲染。没有减面、按距离卸载、降低 DPR 或删除法线贴图。

- **夜晚：8 → 3 passes。** 已有 Cycles 灯光图包含直接光遮挡和间接光，不再额外叠加屏幕 SSAO。主照明、发光提取与水平模糊、垂直模糊与最终输出合并。
- **白天：8 → 7 passes。** 日光/天空并未烘焙，保留原几何法线、SSAO 和两次 AO 滤波。主画面与光晕仍使用精简输出。
- 主画面只写一张 4× MSAA HDR 图。两种灯体颜色均为固定色度、线性红通道为 1，HDR alpha 保存 `1 + lantern.r - window.r`，背景/不发光物体为 1。不再写第二张 HDR 发光图。
- 泛光仍为 sigma3、17 taps、1.5 半分辨率像素间距、0.28 强度；垂直滤波直接并入全分辨率最终输出。色调映射和 sRGB 转换只执行一次。
- alpha 半浮点编码、混合灯体的 MSAA 边缘、合并滤波有少量误差，不宣称像素无损。垂直过滤的采样次数分布也不同，实际收益须测量。
- 自定义 `setupLightMap` 不属于 Three 的普通属性，给每个相关材质补显式 builder 缓存键。新旧路径仍共享材质、几何和纹理。

单独新增 AO 图的候选方案已撤出运行时与部署包：画面/资源收益不足，且夜间会重复调制已经烘焙的照明。其 Blender 脚本与中间证据保留作实验记录，不应误认作当前资源。

当前公开构建 `district-DKUhXJVY.js`，31 个文件 / **11,236,895 字节**；相对前版 11,230,490 字节只增加约 6.41 KB 的代码，不新增场景资源。发布器验证其他游戏 1116 个文件未变。

## 一次对照上报

“新旧对照并上报”锁定当前相机，预热两套完整管线，按旧/新/新/旧顺序各连续渲染 10 秒。一次提交各轮统计、GPU 原始通道、帧间隔和最近 1800 帧。ABBA 可缓解线性温度漂移，不能保证消除热降频。

测量期间锁定交互，后台、窗口变化、测量期出现新管线均明确报错；结束或失败后恢复管线、连续渲染/巡游状态。原 30 秒巡游仍能测试全路线；固定视角对照不能替代路线目标。

性能面板“查看旧管线”可检查画面；`?pipeline=reference` 访问参考路径，默认 `static`。probe 和 render=reference 诊断默认选择参考路径；比较旧 post 参数时同时指定 pipeline=reference。

## 验证边界

17 个路线、计时、帧间隔、历史上报和相机条件回归测试通过。最终公开页证据在 `artifacts/district-public/static-pipeline-release/`；其他 static-pipeline 目录为候选过程，不能替代最终验证。

软件 GPU 仅用于功能、图像与同环境相对测量。**iPhone 3 / 5 ms 未达标**，最新实机结果见下节；参考路径额外目标在切换/对照后会留存，所以对照期间内存并非只加载新版的占用。

最终夜景三视角新旧平均 RGB 差为 0.072 / 0.171 / 0.516（0–255），最大通道差 10 / 7 / 7；没有候选 AO 方案的黑墙/异常亮块。全景 draws 120 → 59，稳定通道 8 → 3。

白天三视角的最大 RGB 差均为 1 / 255，稳定 7 passes。日夜画面对照来自公开构建 DUnVcBln；最终 DKUhXJVY 仅修正基准相机条件比较，渲染文件和资源相同，且最终构建再次执行了新旧管线切换与上报。

完整自动对照已从公开按钮保存报告 `1b9b9e6b-4744-4d09-862b-b875024f9114`（桌面 SwiftShader，不能与 iPhone 报告混合）。旧/新/新/旧四轮分别 3/4/4/4 个测量帧，GPU 样本合计旧 3、新 4；中位数 3239.340 → 2809.585 ms，约 13.3% 的粗略相对下降。样本少且为软件渲染，仅用于流程和同环境方向检查，绝不是手机或硬件 GPU 性能结论。无新建管线、无运行错误，API 已接受并持久化报告，未触及 2 MiB 限制。

相机归一化会产生约 1e-14 m 浮点舍入。相同条件判定容忍 ≤1e-7 m 的差值，真实相机/目标移动和窗口变化仍拒绝；相应回归测试通过。

恢复检查实际在测量开始后改变窗口，得到明确的“测量期间窗口尺寸改变”错误；准备阶段在确定测量条件之前改变尺寸不算污染。不会把用户真正的尺寸变化与相机的浮点舍入混为一谈。

最终状态检查 `state.json` 通过：默认持续逐帧渲染、测量期锁定交互、尺寸变化中断、恢复原管线/连续渲染/按钮、失败不残留基准结果，以及恢复后的三个巡游姿态均为 3 passes；运行错误为空。

## 实机结果：8647dd1f

2026-10-21 的 iPhone Edge / Apple GPU 报告确认最终 DKUhXJVY 构建，固定夜景全景、585×982、4× MSAA，四轮共 2391 帧 / 160 GPU 样本。旧版中位数 / P95 **9.458 / 13.170 ms**，新版 **8.622 / 13.021 ms**；本次下降约 8.8% / 1.1%，实际 8 → 3 passes、120 → 59 draws，但 **GPU 3 / 5 ms 目标未通过**。约 60 FPS 提交不能替代该目标。

160 个原始 GPU span/sum/overlap 独立复算一致。固定条件仍有明显轮间波动，不能将本次 8.8% 宣称为稳定收益。新版主绘制窗口中位数 7.790 ms，各通道重叠，不能相加或当作独占成本。

合并垂直光晕后，其滤波从半分辨率搬到全分辨率，覆盖像素约增加至 4 倍；节省目标/写回与增加采样之间的净收益尚未分离。下一步优先独立比较半分辨率双向光晕，并对主材质/环境反射/月光阴影采样做诊断，不再以 pass 数作为性能结论。完整结果及复算脚本见 [analysis.md](../artifacts/iphone-reports/8647dd1f/analysis.md)。此轮未更改运行时或部署。
