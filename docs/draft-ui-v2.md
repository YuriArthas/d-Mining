# UI 改版 v2：计划

2026-10-28。现有 UI 是 `src/game/ui/kit` 一套青蓝 Roblox 风组件加上各界面，功能完整，但设计感不够。这次大改，按阶段逐个做：每个阶段做完都发布到公开入口，用手机横屏（844×390，DPR 2）截图给用户看；用户说“提交，继续”后提交，再进入下一阶段。

## 约束

- 手机横屏优先，验收用手机视口；PC 只要求 UI 不坏。
- 按 Roblox 游戏做，不用网站的侧栏、表格、长段说明那一套。
- 蛋上方常驻名称和价格。蛋界面直接列出每只宠物的概率，属性放在宠物详情和开蛋结果里（AGENTS.md）。
- 新手提示保持克制，只给一次性提示，不做任务链。
- 画风（3D 场景）不动；这次只改 2D 界面层。
- 不保留旧样式兼容层，旧的类名和 CSS 在各阶段替换时直接删掉。
- 每个阶段结束时，全量测试 0 失败，并更新公开检查脚本的截图。

## 现状问题（2026-10-28 审查，截图在 `output/ui-audit/`）

- **全局**
  - 整屏蓝底蓝框，没有层次。
  - 所有面板都是同一个模板，看不出主题。
  - 只有一种描边字：小字容易糊，说明文字像网页。
- **横屏空间用得差**
  - 奖励、传送站、矿物页大片留空。
  - 蛋列表要滚动，帮助页最后一张卡被截断。
- **HUD**
  - 左栏太重：帮助和设置、背包、金币、大号“下一层”卡片叠在一起，还挡住了场景里的世界名牌。
  - “深度 / 地表”的写法别扭。
- **挖矿时**
  - 底部“出售”“返回地表”两个大按钮，加上左栏，坑道只剩大约一半能看清。
  - 方块血量面板放在屏幕上方中间，离被敲的方块很远，也没有伤害数字。
- **各界面**
  - 商店价格按钮没有动词，“▲9”提升标记太小。
  - 蛋界面布局零散。
  - 设置用文字按钮表示开关状态，应该用开关。
  - 帮助页是大段文字。
  - 加载页的“退出游戏”抢眼。
- **调试入口**
  - 左下角“解锁”按钮在公开版对所有人可见。
  - 屏幕中间的“调试”只在 `?debug=1` 时出现，不算问题。

## 阶段

### U0 样稿定方向

- 做 2–3 套风格样稿，都是自包含 HTML，按 844×390 渲染。每套包含：
  - 地表主界面；
  - 挖矿中的主界面；
  - 宠物面板。
- 每套样稿要定下：配色和材质层次（深色外框加浅色内容区，或其他方案）、字号层级（3–4 级）、主按钮和次按钮、标题横幅、货币和数量的显示方式、开关、页签、角标。
- 用户挑一套，或者指定混搭。之后的阶段都按选定的方向做。
- **验收**：用户选定方向。

### U1 设计基础（kit）

- 按选定方向重写 `kit/`：
  - `tokens.css`：颜色、字号层级、圆角、阴影、描边。
  - `panel.tsx`/`panel.css`：面板外框、标题横幅、关闭按钮、页签、两栏横屏布局。
  - `controls.tsx`：主按钮和次按钮、带价格的购买按钮（动词加价格）、开关、步进器、角标、进度条、货币标签。
  - 动效：面板弹入、按钮按下、获得物品时的弹跳和飞入、数字滚动。
- 字体子集按新文案重新生成（`tools/build-ui-fonts.py`）。
- 增加一个只在 `?debug=1` 下能打开的组件样板页，把所有组件放在同一页，方便截图检查。
- 旧界面先接上新的 kit 组件，不改布局，保证不崩。
- **验收**：样板页截图，旧界面套上新 kit 后没有错位。

### U2 主界面 HUD

- **顶栏**
  - 本世界货币放在顶栏，重生倍率放在旁边。
  - 背包容量用小条显示，满了变色、点一下就出售。
  - 增益效果放在顶栏下方一排小图标里。
- **深度**
  - 地表显示世界名。
  - 地下显示“第 N 层 · 深度 X 米”，下面一条细进度条表示到下一层的进度。
  - 原来大号的“下一层”卡片并进这条进度条，不再单独占位。
- **右侧主功能**：宠物和商店做大、做突出；奖励和重生次之；角标统一。
- **菜单**：帮助和设置合成一个菜单按钮。
- **底部**
  - “出售”“返回地表”缩成小按钮，放在不挡坑道的角落。
  - 背包满时，“出售”放大并发光提示。
- **调试**：“解锁”按钮只在 `?debug=1` 时出现。
- **留出场景空间**：HUD 不挡世界名牌和蛋台标签，挖矿时坑道中部清空。
- **验收**：地表、挖矿中、背包满、增益中、重生可用这 5 个状态各截一张图。

### U3 挖矿反馈

- 方块血条挂在被敲的方块上方，跟随屏幕投影。
- 显示方块名称和售价；镐子等级不够时标红，写“需要 Lv.X 镐子”。
- 每次敲击跳出伤害数字；最后一击用更大的字。
- 方块碎掉时有一个短暂的弹出效果；矿物拾取提示改成图标飞向背包。
- 只有被瞄准的方块显示这些反馈，不常驻。
- **验收**：敲击中、碎裂、镐子等级不够三个状态的截图，加一段短录屏。

### U4 宠物与背包

- `BagSheet` 宠物页：
  - 横屏两栏：左边宠物网格，右边选中宠物的详情。
  - 详情含两项加成、所属世界货币、金色合成进度。
  - 装备栏常驻顶部；“装备最佳”有更好组合时高亮。
- 矿物页和材料仓：
  - 材料仓做成门票进度卡片。
  - 矿物网格加上售价。
  - 底部放“全部出售”和“传送出售”。
- 背包升级入口留在背包里。
- **验收**：空背包、满背包、可合成金色、材料仓凑齐这几种状态的截图。

### U5 蛋界面与开蛋

- `EggSheet`：
  - 蛋大图放左边，概率表放右边，一屏放下、不滚动。
  - 按钮沿用现有的“开蛋”和“自动开蛋”。
  - 价格和本世界货币放在按钮里。
- 开蛋结果：
  - 蛋摇晃、碎开，宠物弹出。
  - 稀有度用颜色和光效区分。
  - 结果卡显示两项加成，并标出“比当前队伍强”。
- **验收**：开蛋、自动开蛋中、出稀有宠物、钱不够这几种状态的截图，加录屏。

### U6 商店

- `ShopPanel`（3D 展示柜外层）：
  - 镐子页的主按钮写“购买 · 价格”“强化 +N · 价格”“装备”或“已装备”。
  - 提升幅度用大号的“伤害 ×1.5”标签显示，不再是“▲9”。
  - 门槛等级、所属世界和货币一眼能看到。
  - 背包页和其他页跟镐子页统一。
- **验收**：买不起、可购买、可强化、强化满、跨世界货币这几种状态的截图。

### I0 多语言（2026-10-28 插入，U7 之前）

- 用户要求游戏支持多语言：英语（默认）、简体中文、印尼语、越南语（2026-10-28）。
- 做法：
  - 玩家看得到的文字一律用中文原文写在 `tr('…')` 里（gettext 风格，中文是键），参数写成 `{名字}`。
  - 译文表：`src/game/i18n/en.json`、`id.json`、`vi.json`。
  - 语言按 `?lang=`、本机保存的选择的顺序决定，都没有就用英语；页面加载时定下来，切换语言就保存进度并刷新页面，所以内容名称、提示、3D 标签都在加载时生成好。
  - 菜单里加语言切换。
- 数字单位按语言：中文用万、亿，其他语言用 K、M、B；深度写成“米”或“m”。
- 越南语的声调字母 Fredoka 没有，越南语页面整页改用 Noto 的越南语子集（`Mining Display Vi`），避免一个词里混两种字体；3D 牌子字体也收进各语言的字母。
- 一个中文词在英文里有两个意思时，用 `§` 加语境区分，比如 `tr('装备§gear')`（页签 Gear）和 `tr('装备')`（按钮 Equip）。
- 进入游戏前的静态加载页由 `index.html` 里的 `data-en` 和开场脚本切换。
- 数据文件里的中文（`economy.json` 的货币名、休整大厅场景里的牌子文字）也走 `tr()`。
- 检查：
  - `tools/tests/i18n.test.mjs`：每条 `tr()` 都有英文、参数一致、没有遗漏的中文（报错文字和调试页除外）、英文表里没有用不到的条目。
  - `tools/check-i18n-mobile.cjs`：英语、印尼语、越南语各跑一遍，每个界面截图，页面里不能有中文，文字不能溢出；菜单能切到中文再切到越南语。
- 以后：U7 到 U9 的新文字从一开始就写成 `tr()`，同时补齐三张译文表。

### U7 世界传送门、传送站与重生

- `PortalSheet`：世界卡片，标出门票的货币和材料进度（材料仓）、所需镐子等级、是否已开放。
- `StationSheet`：地表传送站（踩上传送台弹出），列出这个世界的地表和 6 个休整层，已到达的可以传送，没到的显示还差多深。
- `RebirthSheet`：重生前后对比和庆祝动画。
- **验收**：每个界面在可用和不可用两种状态下各截一张图。

### U8 奖励、设置、帮助、加载

- 奖励和扭蛋机：横屏铺满，可领取的高亮。
- 设置：改成开关和滑块，并入 U2 的菜单。
- 帮助：改成 4–6 张图示卡片（移动、挖矿、出售、宠物、升级、世界），每张一句话。
- 加载页：进度和提示；“退出游戏”降为次要按钮。
- **验收**：每个界面截一张图。

### U9 收尾

- 删除 `legacy.css` 和各界面里不再使用的样式与组件。
- 全量截图：手机横屏全部界面加 PC 抽查，确认 PC 不坏。
- 检查文字：同一概念全游戏只用一个说法（货币名、背包、材料仓、门票、层）。
- 全量测试 0 失败，更新公开检查脚本。
- **验收**：用户整体过一遍。
