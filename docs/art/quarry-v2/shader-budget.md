# 表层模型消失：纹理采样器超限

## 2026-10-04 问题与证据

用户截图中，Tripo 传送地标、外围围墙及树木消失，模型阴影、简单材质文字与矿棚仍在。草地的道路着色也没有正常绘制。

公开旧版的实际 WebGL 已链接程序审计发现，完整 Tripo 材质使用 **17 个采样器**：

- 10 盏聚光灯阴影 + 1 盏月光阴影：11。
- 颜色、法线、粗糙度、金属度：4。即使 ORM 共用纹理，Three 的不同 uniform 仍占不同单元。
- 环境图、Three r186 的 DFG 查询纹理：2。

WebGL2 只保证每个片元着色器 16 个纹理单元。之前的公开浏览器检查使用 SwiftShader，它提供 32 个，无法暴露 16 单元显卡上的程序链接失败。不能把这个验证环境的画面通过当作硬件兼容性通过。阴影深度程序的采样器更少，因此物体可能消失而影子保留。

旧版实际采样器清单：`artifacts/shader-budget/before.json`。未读取用户显卡日志，用户具体硬件上限尚未实测；但旧版 17 超出最低保证是明确的兼容性错误。

## 修复

光源是否照明与是否额外生成阴影分开配置。保留所有光源的位置、颜色、亮度，以及所有模型与贴图；广场、矿棚立面、服务区补光不再分别生成阴影。保留月光、矿坑主灯、两盏蛋区灯、三盏传送区灯的阴影。

完整材质降为 **13 个采样器**，为 16 单元显卡留 3 个余量。不按设备偷偷隐藏场景或移除模型。

## 回归约束

- `quarry-textures.test.mjs` 从全部实际发布 GLB 材质与灯光配置计算采样器预算（包含环境图和 DFG），要求不超过 14。
- `tools/check-surface-render.cjs` 只访问公开列表与 Mining 测试版，审计真实链接程序的 active sampler uniforms，同样要求不超过 14，并收集页面、控制台及 HTTP 错误。
- 公开检查覆盖未解锁传送模型、外围场景与蛋区；等待实际提交帧推进后再截图，避免只等固定秒数拿到旧画面。
- 软件 GPU 的运行结果不代表用户实际硬件帧率，也不宣称已在用户显卡上实测。

本轮结果：构建发布与公开产物哈希核验通过，正式入口未变更。针对性测试 6/6 通过。公开浏览器审计实测最大 13 个采样器，无页面、控制台或 HTTP 错误，已实际检查两张截图（传送模型/外围与蛋区）。记录：`artifacts/shader-budget/public-report.json`。
