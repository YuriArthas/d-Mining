# 加载诊断与木质压顶

## 加载诊断（未修改加载策略）

对已经发布的 V30 公开测试入口运行 `tools/diagnose-startup.cjs`。采集 CPU profile、资源时间线、主线程长任务、WebGL 调用、GPU 上传 fence 生命周期和 worker 任务。没有更换材质或降低分辨率；采集至可玩且完成三帧后停止 RAF，以免后续运行污染启动数据。未进行本地私有游戏验证。

证据：`artifacts/startup-audit/{cold,warm}.{json,cpuprofile}`；细分 GPU 查询和 worker 后的复测：`artifacts/startup-audit-detailed/cold.{json,cpuprofile}`。文件名 warm 表示同浏览器重载，**不表示成功命中缓存**。服务器使用 SwiftShader，绝对耗时不等同于用户硬件。

细分复测结果：

| 阶段/操作 | 本次耗时 | 解释 |
| --- | ---: | --- |
| 出生点体素与碰撞准备 | 启动后 0.669s 完成 | 与资源加载并行，场景挂载时待办为零 |
| 77 个模型的下载及 gzip 解压累计 | 1.157s | 每个模型的 downloadMs 含读流、解压，不能当作纯网络耗时 |
| 77 个模型的解析、贴图转换、上传及等待累计 | 5.128s | 每个模型的 decodeMs 含上传等待，不是纯解码 CPU 时间 |
| 其中 208 次逐纹理上传 fence 生命周期 | 3.350s | 单纹理 initTexture → flush → 每 8ms 轮询，等待完才能上传下一张 |
| 表层准备整体 | 6.682s | 包括上述两阶段、模型摆放、围墙裁切、批次组装等 |
| 首个带完整场景的 RAF 回调 | **4.169s 连续阻塞** | 用户看到的“下载后卡住”主要集中在此 |
| 首帧内生成地下九层场景 | 0.810s | `RoomFacilities.sync()` 同步创建所有楼层，构造/压缩/合并几何 |
| 启动内 getProgramInfoLog 总计 | 3.280s | 首帧逐个初始化 shader 时同步等待链接结果；不是日志文本处理本身慢 |
| 天空昼夜环境捕获 | 0.019s | 此次并非主要问题 |

本次共创建 33 个 shader program。CPU profile 将主要停顿定位到 Three `WebGLProgram.onFirstUse` / `getUniforms`；进一步包装 WebGL 查询证实等待集中在 `getProgramInfoLog`。仅关闭错误检查会把等待转移到其他首次使用调用，不能视为解决编译问题。

208 次 transcode worker 响应延迟合计 1.129s，包含排队/消息传递且可能重叠，不是独立可相加的 CPU 解码时间。上传 fence 总时间也包含 GPU 已排队绘制及轮询粒度，不能解读成纹理传输本身需要 3.35s。

另一个已确认问题是缓存：公开静态响应只有 `Cache-Control: no-cache`，没有 ETag/Last-Modified；`../d-game1/server/serve.mjs` 也没有条件请求或压缩响应处理。这次冷载和重载都传输了约 26.07 MB，模型部分约 21.09 MB。主 JS 为 4,336,374 字节，本次无 HTTP 内容压缩。重载在软件渲染环境中耗时波动很大，不能拿它与冷载比较硬件性能。

建议实施顺序：

1. 在实际灯光/材质状态就绪后异步预编译首屏 shader，避免第一帧逐个同步等待；保留真实编译错误检查。不为远处所有楼层预编译不需要的首屏变体。
2. 保留加载峰值限制，将逐纹理 fence 改为受字节预算约束的小批量上传；下载预取与单模型解码流水并行，避免恢复无限并发。
3. 把静态几何构建/顶点合并尽量移至构建期；地下楼层准备移出首帧，分任务完成后常驻，不能按玩家距离卸载普通场景。
4. 带内容哈希的静态资源使用长期 immutable 缓存，HTML 保持及时更新；JS/CSS 预压缩。限制变更到测试资源策略，避免顺带修改正式游戏发布行为。
5. 区分下载、解析、上传、几何准备、shader 预热与首帧状态。目前“77/77 / 正在准备画面”在同步大任务之前设置，浏览器来不及绘制，用户只能看到旧进度。

本轮完成诊断，未把以上优化方案当作已实现。

## 木质压顶

用户指出围墙顶端草皮像悬浮薄片。将悬挑的 2.4m 外沿替换为 **0.32m 厚的木质压顶**，前缘、底面与顶面均为木材；草地从实际土体上方开始。保留台面高度、完整封闭的地形和原碰撞，木墙接在压顶下方。

新增一张 64×64 RGBA 程序木板纹理，含板缝和克制的木纹，mipmap 缩小；无金属度，不新增模型下载。土体现在为 176 三角面、三个材质批次。来源是 `BoundaryCore.ts` 的程序地形和纹理，不是 Tripo/Blender 资产。

`src/game/presentation/BoundaryCore.ts` SHA-256：`b3ba95bc9ceb935ef814039ddfa9ab8439ae3d08be1fd66d5d5cf35e8397c747`。

构建、两项封闭边/台阶落地回归及公开资源哈希校验通过。公开页面运行检查通过，无页面或 shader 错误；已查看斜角台阶与墙面截图，木压顶厚度、木板顶面及草地内缘可见，火把照明保留。公开视觉与运行检查产物目录为 `artifacts/terrace-timber-cap/`。
