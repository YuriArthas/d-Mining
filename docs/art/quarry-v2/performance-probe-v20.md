# V20：手机公开性能对照

用户截图：43.2 FPS、RAF 43.2 Hz、逻辑 CPU 1.4 ms、提交 CPU 4.0 ms、109 次绘制、20.1 万三角面；调度跳过 0%、fence 等待跳帧 0%、同步 0 ms，GPU 计时未开启。

这张图排除了该时刻限帧器/手动 fence 丢帧的直接影响，但 23.1 ms 帧间隔减去两项 CPU 的差值不是实测 GPU 耗时。剩余需要区分 3D 填充/着色、阴影、呈现/合成等负载。

## 公开操作

Mining 测试版左上角“性能诊断”→“开始诊断”。站在实际卡顿位置，保持镜头与手机朝向，约 40 秒自动完成：

1. 正常画面（前）
2. 暂停 3D 绘制：逻辑继续，观察 RAF；提交 FPS 为 0 是有意停止，不能标为 GPU 等待跳帧。
3. 纯色材质：使用临时 overrideMaterial，去掉正常材质的光照/纹理运算，仅供对照。
4. 关闭阴影：其他真实灯光保留。
5. 宽高各减半：像素量约为原来的 1/4；正常游戏 DPR 设置不变。
6. 正常画面（后）：用于检查温度/系统负载漂移。

每阶段 6 秒，前 2 秒及跨过预热边界的窗口不入结果；按窗口实际时长加权。无有效样本显示 —。结束、取消或切到后台均恢复正常设置，不重建场景，不影响背包数据。结果可一键复制（含 UA 和 CPU 数据），也可拍摄结果表。

正常模式继续保持 V19 的设置，包括水面反射关闭；本轮没有根据截图就改变正常灯光、模型和分辨率。

## 解释边界

- 暂停绘制/纯色显著改善，说明正常 3D 路径的负载值得优先处理；不能仅凭暂停结果断言具体 GPU 耗时。
- 1/4 像素量明显改善，支持像素着色/填充/渲染目标带宽方向。
- 关闭阴影明显改善，支持阴影采样及其材质程序成本方向。
- 纯色改善而低像素/阴影改善不明显，需要继续区分材质、灯数和 CPU 提交，不直接声称面数是原因。
- 前后正常画面差很多时，不把中间各项差值当稳定收益，需重新固定条件。
- 软件 GPU/人为 RAF 节流的服务器结果只验证诊断功能，不能代替用户手机数据。

代码：`PerformanceProbe.ts`、`PerformanceProbeUi.tsx`，公开检查 `tools/check-performance-probe.cjs`，证据 `artifacts/performance-probe-v20/`。

## 本轮验证

- TypeScript / 构建 / 公开资源哈希校验通过，正式 Mining 文件保持不变。
- 17 项相关测试通过（采样、诊断阶段、调度、提交模式）；`git diff --check` 通过。
- 公开桌面检查通过：暂停绘制、纯色、关闭阴影、像素量降至 1/4 四种模式依次生效；缓冲区从 1280×720 降至 640×360，结束恢复原尺寸和阴影，场景不重载。
- 复制、取消、关闭入口均通过，页面无错误。
- 服务器使用 SwiftShader 并人为将 RAF 延迟 400ms，只验证功能。部分阶段因软件渲染/编译超出采样窗口，没有有效样本，界面显示 —、复制报告明确写“无有效样本”，不用于手机性能推断。
- 检查脚本改为页内原子捕获状态，避免跨进程多次读取期间阶段已结束，误把恢复后的阴影状态当成关闭失败。
