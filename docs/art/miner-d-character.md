# D 小探险家：新主角（2026-10-29）

用户觉得原来的 A 矿工和现在的画面风格不兼容，而且明显偏暗。原因见下文“A 为什么暗”。处理过程：
1. 用 Image 2.5 以游戏实景截图为背景，出了 4 个候选主角；
2. 用户选了 D「卡通小探险家」，要求重新走 Tripo3D API 生成模型，再由我自己绑骨骼；
3. 因为现有动作兼容 Roblox R15、骨骼位置比较特殊，权重要借鉴 A 的。

## A 为什么暗

不是法线问题：顶点法线和三角形朝向完全一致，没有反向的面；模型里也没有法线贴图。原因有两条：
- Tripo 把明暗烤进了贴图，颜色也偏深。贴图实际用到部分的明暗中位数是 0.40，而它的概念图是 0.82。
- 观感第三步给建筑和树加了提亮和背光补光，角色材质没有加。

在公开版上把 A 的材质颜色乘 5（线性空间），亮度就接近概念图。

## 绑骨骼（`tools/rig-miner-d.py`）

骨骼和权重都借自已上线的 A 矿工（`src/game/assets/character/miner-a.glb`）。骨骼层级、命名和静止姿势都与 A 相同：16 根 R15 骨骼，Root 在胯下，静止旋转全是单位四元数。因此动作、代码手调的挥镐和跳跃、镐子挂右手、背包挂上半身都直接复用。

**关节位置**
- 两个身体都转成身高 1.85 米、+Y 朝前。
- 用网格截面找同样的标志点。截面按网格拓扑连成闭合环，不按点的间隙分段，因为大平面上交点稀，那样会把同一个躯干拆开。A 的 GLB 在 UV 接缝处拆了顶点，先按位置焊接再连环。

  | 标志点 | A | D |
  |---|---|---|
  | 胯下 | 0.770 | 0.738 |
  | 腋下 | 1.146 | 1.082 |
  | 颈部最细处 | 1.466 | 1.386 |
  | 手指尖 | 0.608 | 0.583 |

- 搬关节的规则：
  - 躯干和头按"鞋底—胯下—颈—头顶"三段的相对高度，从 A 搬到 D；
  - 髋、膝、踝按高度段定高度，再对准 D 的腿截面中心；
  - 肩的横向位置按两身体在该高度的肩宽比例；
  - 肘、腕按 A 在"肩到指尖"之间的比例定高度，再对准 D 的手臂截面中心。手臂在腋下以上还和躯干连着，那段截面取躯干环在腋下躯干宽度以外的部分。
- 膝、踝枢轴放在截面中心，鞋底长轴用来校正脚掌朝向，这两步和 A 的脚本相同。

**权重**
1. 按骨骼把 A 的网格变形到 D 的比例：每根骨骼沿骨方向按长度比缩放、横向按截面宽度比缩放，再转到 D 的骨骼方向。
2. 对 D 的每个顶点，在变形后的 A 网格上找最近的表面点，按它在三角形里的位置插值出 A 的最终权重。最远的点距离 0.133 米，是 D 独有的部件，比如后腰包。
3. 修正：只看最近表面会出错，因为 D 的肚子比 A 更往前凸，胸口和腰包就被绑到了 A 垂在身前的手上。
   - 手指尖到腋下之间，从中线附近开始的截面环（躯干、腿）以外，并且通过网格连到手臂中线的点算手臂，只保留手臂骨骼。拇指借手套连进来；腰带上的工具包只通过腰带相连，进不来。
   - 其余的点去掉手臂骨骼。
   - 腋下到头部分界线之间，手臂权重按离中线的距离平滑渐变，在腋下躯干半宽的 70%–120% 之间从 0 到满。
   - 头部权重在头部分界线以下 8 厘米内平滑淡出，领口跟上身走。
   - 之后照 A 的做法：头和头盔整块跟头，膝部按腿上高度重刷，鞋底整块跟脚。前臂也按同样办法重刷：A 的肘很高、手套很长，转过来后 D 的前臂原本大多跟了手。
   - 最多 4 根骨骼，并归一化。
4. 结果：
   - 跑步时相邻顶点的最大拉伸 4.79 倍（测试上限 5），走路 4.0 倍，待机 2.6 倍；最长拉伸边 0.18 米（上限 0.2）。
   - 修正前，跑步里超过 5 倍的边有 363 条，最大 26 倍。
   - 四个动作首尾接缝的误差都在 1e-6 量级。

**动作烘焙**和 A 完全相同：RAB 待机、行走、跑步，A 字站姿偏转，两节腿膝部重定向，根位移，接缝平滑。动作数据仍是 `assets-source/miner-a/rab-*.json`。

**贴图提亮**
- D 的贴图也带了烤进去的明暗，用到部分的明暗中位数 0.46。在游戏里，正面的脸和衬衫比场景暗一档。
- 导出前给 sRGB 值取 0.7 次方再乘 1.15，暗部提得多、亮部几乎不动。提亮后的贴图是 `assets-source/miner-d/miner-d-color-lifted.jpg`。
- 导出器写的是打包图片的原始数据，所以要重新加载提亮后的文件、换进材质。

## 角色补光（2026-10-29）

用户反馈：场景调性满意，但主角和宠物在背光时太暗。

**原因**：场景静态物体有背光面补光（`albedoLift.ts`），不朝上的面，环境光放大到约 5 倍。主角和宠物没有这一项，背光那一面只吃到 0.7 的天光，而太阳是 3.18。

**做法**（`src/game/presentation/characterFill.ts`）：主角、身上的镐子和背包、宠物的身体和脸，材质都加两项补光。两项都是放大原有的天光，不新增光源。所以地下环境光暗时补光也暗，角色不会在矿洞里像在发光。
- `bounce` 2.6：不朝上的面，天光最多放大到 2.6 倍。多出来的部分带一点沙地反光的暖色；倍数为 1 时和原来完全一样。
- `view` 1.2：朝向镜头、又背着太阳的那一面，在上一项基础上再加最多 1.2 倍。不管镜头转到哪，看到的那一面都不会黑，迎光面不受这一项影响。
- 场景的太阳、天光、地面反光、色调都不变。调试页有 `__miningValidation.characterFill({ bounce, view })` 可以实时调。

**测量**：`tools/check-character-light.cjs`，在公开版上进行。
- 主角带两只宠物站在出生点的沙地上，镜头绕 8 个方向，135° 正对太阳。
- 每个方向拍三张：原样、主角材质染黑、宠物材质染黑。变化的像素就是主角或宠物，取它们的平均亮度。

| 补光 | 主角最暗→最亮 | 主角逆光/顺光 | 宠物最暗→最亮 | 宠物逆光/顺光 |
|---|---|---|---|---|
| 关（原样） | 0.44 → 0.73 | 0.60 | 0.57 → 0.84 | 0.68 |
| 默认（2.6 / 1.2，采用） | 0.70 → 0.78 | 0.90 | 0.79 → 0.89 | 0.89 |
| 强（3.6 / 1.8，仅 r1） | 0.80 → 0.83 | 0.96 | 0.84 → 0.92 | 0.91 |

- 前两行是最终版本 `final` 的结果，强档只在 r1 测过（r1 的关、默认两档与 `final` 相差不超过 0.1）。
- 默认档：正对太阳（135°）时主角从 0.44 提到 0.71，背光的几个方向提 40%–60%；顺光方向只提 6%–20%，明暗层次还在。
- 强档开始发白发平，不采用。
- 地下第一个大厅（老矿井）开着补光对比过：角色和大厅的暖光一致，不显得发光。
- 截图在 `artifacts/character-light/`，其中 `r1` 是三档对比，`final` 是最终版本。
