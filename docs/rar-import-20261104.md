## 改了什么，为什么这样改

### 1. 地表移除地下灯光的渲染成本

`src/game/presentation/CaveLights.ts:22` 默认隐藏灯组，`:40` 根据地表光照比例切换可见性。地下仍保持 6 个场景点光源槽位和 1 个头灯，共 7 盏；没有删除模型、减少场景几何或按角色距离卸载普通物体。

此前灯即使强度为零，也仍进入 Three 的灯列表。当前安装的 Three 0.186.1 WebGLRenderer 在 `projectObject` 遇到不可见父节点时停止遍历；WebGLPrograms 将点光源数量纳入程序参数和缓存键。因此隐藏灯组确实让地表程序排除地下点光源，而仅将强度归零做不到这一点。地下保持固定灯数，则避免随厅堂灯数变化不断切换程序。

推断目的：降低地表灯光计算成本，同时保留地下照明。实际 GPU 收益没有硬件测量，不能由灯数量直接换算帧率。

### 2. 为有灯／无灯两种状态提前编译

`src/game/presentation/prepareShaders.ts:30` 允许将隐藏的地下灯复制进预热场景；`:62` 分别执行无地下灯、有地下灯两轮预热。

这与上一项成套：灯数量进入着色器程序键，如果只预热地表状态，第一次下矿会临时编译另一套程序。新增预热把这部分工作放到加载阶段。代价是加载期预热工作和程序缓存可能增加；不能简单声称加载也更快。

### 3. 关闭 MSAA，描边同步取消 alpha-to-coverage

`src/game/config.ts:6` 新增 `antialias: false`，由 `src/App.tsx` 传给 Canvas；`SelectionOutline.ts` 取消 `alphaToCoverage`。像素比例上限仍是 1.5，没有降低分辨率上限。

推断目的：减少多重采样的存储、带宽和 resolve 等成本。描边同步调整符合取消 MSAA 后的路径。代价是轮廓边缘可能更锯齿。原注释把成本从约 9 倍降到 2.25 倍的说法不能作为实测结论：MSAA 不意味着每个像素都执行四次完整片元着色，采样数和收益依赖硬件。

### 4. 单独提供性能分析构建

`package.json` 增加 `build:profile`；`vite.config.ts:46` 只在 profile 模式打开 source map 并关闭 JS/CSS 压缩；`server/serve.mjs` 增加 `.map` MIME 类型。

推断目的：方便 DevTools 把耗时和调用栈对应到源码。正常 build 继续压缩。原 RAR 中主 JS 是 16,095,190 字节，并含 source map；本轮 profile 重建的主 JS 与原包逐字节相同，SHA-256 为 `20311437800aa9efcae824eadf9e1f9134ce506f53985780297e885e3f5d19fe`。新交付 dist 使用正常生产构建。

### 5. 默认中文，语言列表中文优先

`src/boot/loading.js` 和 `src/game/i18n/i18n.ts:13` 将无参数、无已存语言偏好时的默认语言从英语改成中文；`zh.json` 与 `en.json` 互换排序。显式 `?lang=` 和已有语言偏好仍优先。游戏名称文案本身没有变化。

推断目的：让首次进入的中文用户直接看到中文，并让加载画面与游戏内语言保持一致。
