# 单机挖矿游戏 MVP Draft

状态：Draft。P0、基础移动/相机、稀疏地形与独立渲染/碰撞、多矿物外观、电脑鼠标选格及手机触点长按已实现并完成相应自动/浏览器验证；目标手机性能和完整人工验收仍未完成。[P3A 背包与售卖 API](phase3-inventory-sale.md) 保持解耦优先；采集支持多格与多物品批次，由挖矿判断满包，背包 add 始终完整加入且不受容量限制，最小画面供用户简单检查。P3A 已实现独立 API、挖矿准入/完整入包、售卖圈与最小表现，并完成本地自动与浏览器检查；已实现 [P3B.1 UI 背包升级](phase3b-backpack-upgrade.md)；已实现 [P3B.2 血量、敲击与镐子升级](phase3b-mining-combat.md)；[P3C 矿物体积与独立售价](phase3c-item-volume.md) 已接通，实际存档读写后置，主角/镐子动作可跳过。[P3D 地下房间](phase3d-underground-rooms.md) 已接入并完成本地、公网双端验证。[P3E 矿层分布](phase3e-depth-strata.md) 已实现，浅中深层由独立概率表生成。

日期：2026-10-02；最新范围更新：2026-10-03。

依据：本轮讨论、用户提供的《外包游戏技术要求.pdf》、同级项目当前技术栈。

本文记录已确认的产品边界、建议的实现方案和分阶段验收。写入计划不代表功能已经实现或通过验收。标为“建议”“暂定”的内容属于可调整方案，不冒充用户已确认需求。

## 1. 已确认的方向

| 项目 | 决定 |
| --- | --- |
| 类型 | 浏览器单机挖矿游戏，参考 Mining Simulator 2 的挖矿与成长体验 |
| 平台 | 电脑和手机，均仅支持横屏游玩 |
| 视角 | 接近原作的第三人称自由移动、自由转镜头 |
| 核心玩法 | 挖矿、深入地下、找矿、出售、升级装备 |
| 宠物定位 | 开蛋抽卡获得的简单加成，不以复杂宠物玩法为中心 |
| 主角 | MVP 使用圆柱占位 |
| 工具表现 | 用户允许跳过主角与动作，当前不作为推进背包/售卖的前置条件 |
| 宠物表现 | 圆球加 `LVL` 数字，后续再替换正式模型 |
| 当前售卖入口 | 地表圆圈；角色落地进入后自动全部出售，一次进入只结算一次 |
| 体积与价格 | 按矿物单位体积计容，数量 × 单价售卖；临时数值满足售价增长 > 血量增长 > 体积增长 |
| 升级入口 | 点击 HUD 的“升级”打开镐子/背包 UI；本次不增加升级圆圈；镐子见 P3B.2 |
| 背包架构 | 独立批量物品 API，不认识方块或采集队列；持久化契约提前设计，表现只读快照并发命令 |
| 容量规则 | 背包只提供 isFull 查询，add 不受容量限制；挖矿自行决定已满则停止，未满则采集并加入全部产物 |
| 采集边界 | 一次操作可含多格、多种/多数量物品；业务操作、物品批次、Worker 计算任务独立定义 |
| 性能 | 手机也以稳定 60 FPS 为目标，渲染上限 60 FPS；30 FPS 不算达到本项目目标 |
| 优先质量 | 地形正确且流畅，相机舒服；当前 P3A 优先保证模块解耦，再跑通功能和最小表现 |
| 当前工作 | 优先跑通背包、挖矿入账、自动售卖底层 API；助手负责正确性验证，用户简单检查画面 |
| 流程范围 | 用户最新决定：只保留退出，删除暂停、继续、重开和专门的后台处理 |

## 2. MVP 内容范围

核心循环：

```text
进入矿区 → 挖矿装包 → 出售获得金币
    → 升级镐子 / 扩充背包 / 开蛋装备宠物
    → 提高挖矿效率 → 进入更深矿层 → 发现更有价值的矿物
```

P3A 已跑通“挖矿装包 → 返回地表 → 踩圈出售”；P3B 接入镐子/背包升级，P3C 接入矿物体积与独立售价，宠物仍在后续范围。

整体 MVP 的后续内容方向如下，具体数量由对应阶段确定：

- 一个地表营地、一座矿坑、少量具有颜色与矿物差异的深度分层。
- 六种矿物外观与分布已存在；P3C 临时表已配置不同体积、血量和单价，正式平衡后续调整。
- P3B.1 接入背包升级，档位与价格暂定；P3B.2 接入镐子升级与单格血量。P3A 的库存模块保持独立。
- 一个蛋池、少量宠物类型、有限装备位和一键装备最佳。
- HUD 显示金币、背包容量、当前深度、目标矿块及其挖掘进度。
- 进入游戏、退出返回列表；有本地存档时加载已有进度。
- P3A 提供返回地表命令及按钮，落点在售卖圈外；取消未提交开采，保留已提交收益与矿坑修改。

MVP 暂不安排多人、交易、排行榜、重生、多世界、限时活动、复杂宠物合成/技能、独立宠物战斗或正式美术制作。

矿坑建议使用有限边界和有限深度，边界不可挖，并有可见提示。暂不引入自动定时重置矿坑；挖掘变化随存档保留。后续是否加入矿坑刷新，需要单独定义保留与清空规则。

## 3. 技术栈与交付

| 部分 | 方案 |
| --- | --- |
| 开发语言 | TypeScript |
| 界面 | React + HTML/CSS |
| 3D | Three.js + React Three Fiber，WebGL2 |
| 碰撞 | Rapier 3D WASM，胶囊运动学角色控制器 |

| 开发环境 | Node.js 24.x、npm、提交 package-lock.json |

| 存档 | IndexedDB 保存游戏进度；localStorage 仅存少量偏好设置 |
| 音频 | 本地音频或 Web Audio 合成；用户手势后启动 |
| 后续模型 | GLB；当前用程序生成的几何占位 |
| 验证 | 独立逻辑测试、浏览器流程检查、目标手机实机检查 |

依赖参考 `../d-game1` 与 `../d-Block-Blast` 当前版本，并用本项目锁文件固定实际解析结果。本项目独立构建；2026-10-02 用户授权将空入口挂入相邻工程的游戏列表，宿主挂载不影响独立交付。

必须能在干净环境执行：

```bash
npm ci --ignore-scripts
npm run build
```

输出 `dist/index.html` 和全部运行资源；库、Worker、音频和素材不能仅依赖外部 CDN。保留源码、锁文件、构建说明、参数说明和第三方许可清单。

PDF 禁止使用游戏引擎开发，明确允许 Three.js。本方案使用浏览器库和项目自有规则代码。构建成功仅证明产物生成，不代表玩法或手机性能通过。

## 4. 代码职责

按实际功能组织模块，不预建通用 ECS、编辑器或复杂框架。

| 职责 | 内容 |
| --- | --- |
| 规则与配置 | 矿物、装备、宠物、售价、概率、升级与背包结算 |
| 游戏运行时 | 固定时间步进、角色状态、挖掘状态、退出与资源释放 |
| 地形 | 种子生成、分块数据、修改记录、邻块关系与空间查询 |
| 地形表现 | 分块网格、Worker 调度、网格版本、GPU 资源释放 |
| 输入与相机 | 键鼠/触控映射、第三人称跟随、避障与选矿 |
| UI | HUD、商店、开蛋、宠物列表、退出与存档提示 |
| 持久化 | 存档校验、版本识别、保存与恢复 |

背包只处理物品批次、计数和容量查询，add 不检查容量；钱包只处理金额，地形处理世界修改及内部资源更新。挖矿流程自行查询是否满包，再组合采集、掉落与同步入包；售卖组合库存、价格与钱包。区域检测只报告进入/离开，会话层接入售卖、返回与已有地形清理。业务模块可在无 DOM、Three.js 和真实 Worker 的环境验证；UI 只查询和发命令。具体依赖与数据契约见 [P3A](phase3-inventory-sale.md)。

React 负责 UI 和场景挂接。角色位置、镐子挥动、相机和宠物跟随通过帧循环更新对象，不使用每帧 React 状态更新驱动整棵场景。

逻辑使用固定步长，渲染按需插值；规则、矿物生成与开蛋随机源不依赖渲染帧率。音画随机与规则随机分离。固定步长不等同于已经证明跨设备完整回放一致性，MVP 不承诺完整回放系统。

## 5. 地形方案

### 5.1 数据与生成

- 用整数坐标查询唯一稀疏逻辑源：生成规则 + 稀疏修改区间；不分配完整 16³ 格子数组。
- 种子、生成版本和坐标决定基础矿物，分块加载顺序不能改变矿物分布。
- 记录被挖除等修改；重新进入区域时恢复相同地形。
- 深度分层配置矿物权重、硬度与视觉主题，所有核心参数有实际读取位置。
- 逻辑矿区至少 100 × 100 × 2000 格，按需生成；当前 2m 矿格，渲染 16 格/碰撞 8 格的工作区域独立管理，均不是逻辑存储块；近场碰撞先卸载，渲染更远才卸载。

### 5.2 网格与调度

- 渲染和碰撞为两个独立派生系统：渲染贪心合并同显示属性表面，碰撞仅按占据合并；分别拥有 Worker、缓存、版本和加载范围，仅共同读取逻辑源。
- 不为每个矿块建立独立 React 组件、Mesh 或刚体。
- 挖掘后更新受影响的分块；边界变化必须使邻块失效并重建必要表面。
- 相邻分块卸载时，不能把“未加载”误认为真实空洞；边界可见性依据地形数据判断。
- Worker 承担生成和网格构建，主线程分批接收、上传 GPU 并替换几何。
- 每个任务带世界代次和分块版本；丢弃被新挖掘、退出或读档淘汰的结果。
- 合并同一分块的重复任务，限制队列、每帧上传工作量和常驻缓存。
- 挖掘附近与角色下落方向优先；远处任务不能阻塞当前可玩区域。

### 5.3 一致性与移动

- 地形数据是选矿、碰撞、掉落和渲染的共同依据；一次挖除只结算一次。
- 用户已确认使用 Rapier 统一处理普通地形与体素矿区，角色为胶囊运动学控制器；仅附近创建碰撞体，远处卸载，画面和物理加载范围独立管理。
- 支持重力、跳跃、落地、墙面滑动，并处理墙角、高速下落和挖掉脚下方块。
- 对未准备好的区域提前加载并限制进入，不能把它当作空气放任角色坠落。
- 当前开采反馈使用目标高亮与触点提示，主角/镐子动作可跳过。异步网格不能造成可感知的“看着有墙却穿过”或“墙没了却仍挡路”；P3A 增加入包/满包反馈，不引入硬度或动作要求。
- P1.V 采用受影响区块准备完后统一提交数据、网格和碰撞；P2 继续测量并优化提交延迟，不能用碎石表现掩盖不同步。
- 返回地表与读档时，先保证落点和周边地形可用，再允许移动。

## 6. 输入、横屏和相机

### 6.1 输入

- 电脑：暂定 WASD 移动、空格跳跃、鼠标转镜头、持续按键开采；鼠标捕获/拖动方式在 P1 实操确定。
- 手机：左摇杆移动、跳跃按钮；场景触点长按约 180ms 挖掘，此前拖动超过 10px 则观察。挖掘中滑动只切换目标，一次手势不同时转镜头；无独立挖掘按钮或中心准星。
- 两端转换为统一动作；处理多指归属、pointer cancel、松手和 UI 事件隔离。
- 始终使用横屏布局：竖向窗口内整屏顺时针旋转 90°，横向窗口直接铺满；同步转换画布比例、触控坐标与安全区域。不显示旋转提醒，不依赖系统锁屏或全屏 API。
- 不增加切后台状态流程或恢复确认界面。

### 6.2 相机与目标选择

- 第三人称后上方跟随，允许自由水平旋转和受限俯仰。
- 矿格相对角色保留足够通行与观察空间，不能只靠相机避障补救过窄矿道。
- 镜头避障考虑近裁剪面和镜头体积；遇障及时收近，恢复距离平滑。
- 允许看清脚下矿块，验证向下挖掘、落入竖井和贴墙移动时的视野。
- 目标选择沿视线查询网格，显示高亮和挖掘进度；选定目标后只检查角色到命中表面的距离（4 格 / 8 米），不检查射线可见性或遮挡。
- 相机平滑不应造成明显操作延迟；进入商店、返回地表和读档不能发生无理由的突跳。

“相机舒服”需要用户实际游玩确认。自动截图只能验证画面状态，不能替代手感验收。

## 7. 商店、成长与宠物

### 7.1 当前售卖圈

- 地表一个圆圈；依据脚底水平位置、地面高度范围和落地状态判定，地下/空中不能触发。
- 进入自动全部出售，一次进入只结算一次；进入/离开有小幅距离滞回，空包不产生收益。
- 会话层在进入时停止新开采、取消未提交操作，再调用售卖服务，按当前已入包总数量 N 扣矿并增加 N 金币。售卖区内不发起开采；这些组合策略不写入背包、售卖服务或区域检测器。
- 背包与钱包完成同一同步结算后再通知 UI；不弹确认面板，不加入升级 shop。
- 表现显示售卖圈和简单结果提示；触发逻辑与圆环 Mesh 解耦。细分 API 与验证见 [P3A](phase3-inventory-sale.md)。
- P3B.1 的背包升级改为 HUD 按钮打开界面，可随时操作；购买输入不能穿透到场景，关闭恢复输入。与售卖圈分开。

### 7.2 后续装备与开蛋（不属于当前 P3A）

- 镐子影响挖掘力量和/或频率；背包影响容量，参数进入实际规则。
- 挖矿流程查询满包状态并提示；未满时整次采集产物完整入包，满后停止继续挖。背包 add 本身不限制数量或拒收，其他来源也可继续加入。
- 开蛋先完成一次原子结算：扣款、随机结果、宠物入库；动画仅展示结果。
- 关闭商店或退出开蛋动画不能重复扣费、重复领奖或丢失已获得宠物。
- 宠物为圆球加等级文本，装备后跟随并提供配置中的加成；跟随不做物理刚体或寻路。
- 暂定少量装备位；宠物背包上限、重复宠物处理、等级来源与加成叠加规则在 P4 前明确。
- MVP 不做复杂成长系统；等级可以先固定为 1，显示 `LVL 1`，是否随挖矿升级仍属待定。

## 8. 存档、参数与生命周期

实际存档读写留在 P5。P3A 提前定义稳定 ItemId、InventoryDataV1、数据校验和纯数据导出/初始化；业务操作状态和 Worker 请求不进存档，合法超容量库存必须能无损导出和初始化，不创建任何浏览器存储写入。未来存档在完整提交边界取矿坑、背包与金币的一致快照，不能只恢复背包。

以下为 P5 后续范围：存档包含世界种子、生成/规则/存档版本、矿区修改记录、角色安全位置、金币、背包、装备、宠物与规则随机状态。

- 自动保存有节流，并在重要交易后记录；不能只依赖关闭页面时保存。
- 识别损坏和不兼容存档，显示具体问题，不静默覆盖旧进度。
- 退出返回游戏列表，再次进入时加载已有存档；无存档时初始化新进度。
- 存储不可用或配额不足时可继续当前游玩，但明确告知无法保存。
- 退出与卸载释放旧 Worker、几何、材质、纹理、音频、监听器、定时器和临时对象。
- 参数文件记录名称、范围、单位和作用对象；修改重建后，玩法实际读取新值。
- 调试入口提供种子、深度、分块数量、任务队列、内存相关资源计数和帧耗时，正常界面不暴露实现细节。

## 9. 60 FPS 与验证约定

### 9.1 目标设备与负载

依据 PDF，至少覆盖骁龙 7 Gen 3 / 天玑 8100 或 8000 级 Android，以及 iPhone 11（A13、4 GB RAM）。测试记录必须写明实际型号、系统、浏览器、分辨率与画质配置。

目标是稳定 60 FPS，渲染上限 60 FPS，高刷设备也不无上限绘制。可以控制像素比、阴影、粒子和可见距离，但不能以降到 30 FPS 冒充达到目标。

暂定验证场景：

1. 地表移动、商店开关、宠物跟随。
2. 连续挖掘和矿层切换，包含分块边界开采。
3. 快速转镜头、贴墙、向下挖和持续下落。
4. 进入新区域，再返回之前挖过的区域。
5. 连续游玩、退出后重新进入与读档。

### 9.2 证据与门槛

- 最新性能口径：平时维持约 16ms/帧（60Hz 周期约 16.7ms），很偶发的卡顿才可接受，且必须定位到明确原因。频繁加载、连续挖掘等常态操作不能反复超预算；不能只用平均 FPS 判定。
- 同时记录帧间隔分布、P95/P99、明显长帧、主线程任务及可取得的 GPU 计时；长帧应附触发操作和具体耗时来源，原因未定位的不能视为已接受。
- Worker 构建时间、结果等待时间和主线程 GPU 上传时间分开记录。
- 不只报平均 FPS，不能用长时间平均掩盖连续挖掘时的卡顿。
- 暂定每台手机连续游玩至少 15 分钟，并进行至少 20 次退出后重新进入检查；具体统计窗口与允许长帧阈值在 P2 建立实机基线时明确记录。
- 资源与内存应在预热后趋于稳定；缓存有明确上限，不能随探索或重复进入持续无界增长。
- 相机、触控、界面可读性和挖掘反馈需要人工验收。
- 缺少目标手机时，可以报告代码或浏览器检查通过，但手机 60 FPS 和整体验收保持未验证。

## 10. 实施 Phase

### P0：工程基础

- 参考相邻项目版本建立最小 npm 工程，不复制其他游戏玩法或历史验收结论。
- 提供独立入口、本地测试服务器、横屏布局、退出与资源释放。
- P0.5 的配置整理已迁入 P1，随实际功能引入；用户已取消 P0.6 交付基线专项，不再作为 P0 的待办。已有构建与依赖说明保留。
- 本阶段不制作正式模型。2026-10-02 用户授权先挂载空游戏，因此允许对相邻宿主做 Mining 列表与构建接入，并发布到现有 `w-sunjun-public` 站点。

### P1：移动与相机

详细任务、依赖、验收与难度见 [P1 拆分](phase1.md)。

- P1.1（已实现）：简化静态地板、小转角、圆柱、尺寸基线与最小配置入口。
- P1.2（已实现）：双端动作输入与基础旋转视角。
- [P1.V：混合地形与动态矿区验证](phase1-validation.md)，插入 P1.2 之后。
- P1.3：在验证实现上完善固定步长移动、跳跃、Rapier 碰撞和帧调度。
- P1.4：地下相机避障、平滑和近距离观察。
- P1.5：目标方块选择与高亮已接入挖除；按最新要求主角/镐子动作可跳过，不结算资源。
- P1.6：双端联调、参数收敛、退出回归与手感/设备记录。
- 原 P0.5 贯穿上述子项实施，参数随消费者出现而加入；不先搭通用配置系统。
- P1.3/P1.4 按需补充碰撞和相机测试路线，并留可跳回的路径；正式返回地表交互在 P3A，不作为 P1 依赖。

### P2：可破坏矿坑与第一次性能关卡

- 建立有限矿区、种子生成、分块加载和异步网格更新。
- 复用 P1 的目标选择和开采意图，接入挖掘伤害、挖除与角色碰撞联动，先不扩充商店内容。
- 验证分块接缝、连续挖同一块、快速切目标、挖脚下、触底、卸载重载和旧 Worker 结果回流。
- 以接近 MVP 预期的可见范围和挖掘频率测量，不用空场景代替矿坑负载。
- 在目标手机完成首轮性能验证；缺少设备时明确挂起实机结论，不能将 P2 整体标为通过。
- 若地形或相机存在结构性问题，先调整再扩充内容；独立规则工作可以继续，但不能掩盖该阶段未通过。

### P3A：背包与售卖 API（已实现）

详细任务、架构边界、接口语义、验证与难度见 [P3A 拆分](phase3-inventory-sale.md)。

- 先定 ItemBatch、稳定物品 ID、可持久化 DTO 与模块端口；背包接受任意合法物品批次，不依赖方块或采集过程。
- 多格采集接入现有地形实际提交点，挖矿请求入口同步查询 isFull，满则不接受新请求；已经销毁的格子全部 add 入包，不在完成时重新限制容量。背包 add 不检查容量，Worker 准备/取消留在地形内部，不新增业务异步协调机制。
- 所有矿物统一 1 金币；纯售卖 API 与地表圈的进入判定分开。
- 角色踩入圈自动全部出售；返回按钮落在圈外，取消未提交开采并保留已提交数据。
- UI 只显示背包、分类数量、金币、圈和结果提示，并发命令；不承担规则或修改权威数据。
- 助手负责 API 和时序正确性，用户只简单检查可见流程。实际存档读写、升级 shop、差价/硬度平衡、主角动作均不做。

### P3B.1：UI 背包升级

详细边界、难度及验证见 [UI 背包升级](phase3b-backpack-upgrade.md)。

- HUD 点击“升级”的背包页打开界面，不依赖位置或升级圈。
- 背包只新增修改容量 API；升级用例负责档位、购买条件与扣钱，UI 只查询和发命令。
- 暂设容量 100 / 200 / 400，价格 20 / 50 / 100 金币；不做平衡，保留现有物品且不改变 add 的规则。
- 宠物和存档继续后置，差异售价见 P3C。

### P3B.2：矿物血量、敲击与镐子升级

详细模块边界、数值和验证见 [P3B.2](phase3b-mining-combat.md)，整体难度 45/100。

- 当前镐子每次攻击一个格子，每次敲击先查满包；实际销毁后完整入包，底层批量 API 保留。
- 稀疏血量独立于渲染/碰撞缓存；冷却独立于目标和 UI，不通过切目标、松手或升级重置。
- 力量每级增长，攻速每 5 级增长并封顶；金币购买接入统一升级面板。
- 仅显示当前目标的血量；模型、动画、存档和正式数值平衡不在本次范围。

### P3B.3：受损方块裂痕

见 [P3B.3 说明](phase3b-block-cracks.md)，难度 30/100。裂痕按损失血量比例分 10 档，切换目标保留；单独批绘制受损方块，不改变地形或碰撞合并，随渲染区域卸载恢复。

### P3C：矿物体积与独立售价

见 [P3C 说明](phase3c-item-volume.md)，难度 40/100。数量与容量分开，背包注入单位体积、售卖注入单价；每次攻击前只检查当前满包状态，已销毁产物完整入包。UI 分别显示容量、件数与预计金币。

### P3D：地下房间、深度解锁与家中传送

见 [P3D 说明](phase3d-underground-rooms.md)，难度 45/100。400 米、800 米两个局部房间；只按到达深度解锁，从家里传送。房间空洞按坐标生成，售卖和升级复用现有独立 API。

### P3E：矿层分布与首轮成长节奏

见 [P3E 说明](phase3e-depth-strata.md)，难度 35/100。0～400、400～800、800 米以下按配置生成不同矿物分布，物品固有属性与房间解锁继续独立；地表测试矿样移到显式验证入口。

### P3F：各层对齐入口

见 [P3F 说明](phase3f-aligned-entrances.md)，难度 40/100。地表及地下房间地板仅 8×8 格能开采，垂直对齐；表皮一格厚，下方恢复自由开采。

- 完善首次进入、加载存档、既有横屏布局和退出流程；不新增旋转屏幕提示。

### P6：MVP 验收与交付

- 重新验证干净构建、静态子目录部署、全部资源本地加载及 Worker 启动。
- 在约定 Android 和 iPhone 11 上执行完整路线与长时测试，记录帧率、长帧、发热后表现和内存趋势。
