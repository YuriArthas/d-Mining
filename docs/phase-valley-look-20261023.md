# 对照原作：围谷、天空与地面（2026-10-23）

用户拿原作截图对比，说“实话说，对比原作，我们还是没他们好看，想想为什么”。分析见 `tmp/compare/`（脚本 `stats.cjs`、`palette.cjs`）：原作画面上半部被高崖密林塞满，天空只露 9%，而且是饱和亮蓝；地面是又亮又淡的奶油沙和浅草（亮度 0.94、饱和度 0.34），鲜艳颜色留给物件和背景；深色像素 1.5%。我们天空占 23%、偏灰，远山灰蓝，上半部鲜艳色只占 9%；地面橙沙深草（亮度 0.74、饱和度 0.64）；深色像素 4.7%。提了五步改法，用户说“改吧”，这一轮做前两步：地面，以及围谷加天空。工作区 `/root/.t3/worktrees/d-Mining/surface-roblox`，基于 `5986774`。

## 改了什么

- **围谷崖壁**（`surface-game-art/tools/terrain/landscape.ts` 的 `buildCliffs`）：北、西、东三面和南面山脊各一段崖壁，由 77 根程序生成的多面岩柱组成（凸包，7 边形分 5 层收口，柱顶略倾斜），前后两排错开，后排更高。岩面底部暖棕、往上变灰紫，每个面颜色略有差异；柱顶是比柱身还宽、向外伸出的翠绿穹顶（`#5ebc91`），前排约八成柱顶种一两棵树，后排一半种一棵。西、北、东三面崖脚各种两排树。会落进小溪、压到路或进入预留空地的岩柱自动跳过，所以小溪从东北和西面的峡口进出，大门所在的山口保持畅通。
- **南面压低**：白天太阳在西南，南面的高崖和崖前树林会把影子投到传送门和出生点（第一版就出现了大片前景阴影）。南面崖壁后退约 5 米、高度降到 8–13 米，也不再在前面种树；山脊上原有的树林保留。
- **崖壁碰撞**：每根岩柱一个凸包碰撞体（`tools/export-pinewind-scene.mjs` 的 `hullSolid`），角色走不进崖里；崖顶和树够不着，不加碰撞。
- **删掉**：北面那几块灰色巨石、山口两侧的灰色石肩（旧的 Blender `cliff` 模型实例）。远处两条山脊从灰蓝改成偏绿的蓝绿色，现在基本被崖壁挡住。
- **天空**（`src/game/world/environment.ts`、`SurfaceEnvironment.ts`）：地平线从发白的 `#c5ebff` 改为饱和的 `#7cc5f3`，天顶 `#358edf` → `#2a86dd`；云少一些、颜色从灰蓝改成白色。
- **地面**（`terrainTexture.ts`）：沙地 `#f1d9a3` → `#fdf1d6`（第一版先改成的中间值，原来是 `#dfb272`），草地 `#74bf4c` 一族 → `#8fdd7b` 一族；矿井口的沙色边沿同步变浅。
- **沙草描边**（`buildEdging`）：沙地和草地交界处一道 16 厘米宽的浅棕色窄带（`#b99366`），用 0.2 米网格对“到路边的距离”做行进方块得到边界；跨过小溪和矿井口的地方不画。
- **出生点南面那条旧颜色的路**：`JourneyGates.ts` 原来铺了一条 74 米长、不吃烘焙光照、颜色写死成旧沙色的长条，盖在出生点南面的主路上（用户截图前景里那块深色路面）。松风地表上只保留地形边缘（z=104）到第二世界之间的 20 米；地形主路延长到 z=104 接上。
- **树**：自然图集里的树叶颜色提亮（`build_nature.py`，松树尤其），并给自然图集材质加“树冠补光”（`albedoLift.ts` 的 `liftFoliage`，与建筑同一机制、参数单独：材质色略提亮提饱和，白天背阳面补一份中性光，暗角和建筑一样减半）。不然逆光看树林几乎是黑绿色。崖壁的岩面和崖顶也套同一套补光，背阴面不再发黑（画面上部深色像素从 23% 降到 12%）。注意补光里“提亮、提饱和”那一步作用在贴图色上，早于顶点色相乘，所以对只靠顶点色上色的岩面和崖顶不起作用，它们只吃背阳面补光和较轻的暗角。
- **调试工具**：`window.__miningValidation.materialTint(rules)` 按材质名实时乘颜色；`lightingLook({foliage})` 实时调树冠补光；`tools/check-lighting-tone.cjs` 的每组对比可带 `tint`。

## 颜色怎么定的

岩面、崖顶、沙地、草地、树都在公开版里用 `materialTint` 同机位并排试了三到四组（`artifacts/enclosure-tint/`、`artifacts/enclosure-v3/`），再按选中的系数换算回材质颜色（`tmp/compare/apply-tint.mjs`，线性空间相乘）。例外是崖顶：`materialTint` 乘的是材质底色，而提亮那一步的防过曝收缩会把大于 1 的底色整体压暗，所以对套了补光、靠顶点色上色的材质，调色测试不可信（实测系数越大越暗）。崖顶改为直接改顶点色重建两次定下：渲染出来的向阳面约 `#38a26b`，原作 `#37a277`。对照原作取样：岩面 `#897a8b` 一类的灰紫（饱和度 0.12–0.16，底部偏暖棕 `#8d6d5e`），崖顶翠绿 `#37a277`，沙地 `#f6eabc`–`#fef4d2`，草地 `#83dc62`。

## 第四步：传送点的主题装饰和发光传送盘（2026-10-28）

原作每个传送点周围摆该层的主题物件，地上是一圈发光的蓝色传送盘。我们地表有两个传送点：传送站（去本世界各层）和世界传送门（去别的世界）。

- **发光传送盘**：触发区原来只有一道很淡的细环，传送站那道还有一半悬在平台边外。现在触发区上是一块和地面齐平的圆盘：Blender 做暖灰石边加金边（`teleport_pad`），游戏里在上面铺一层不透明的发光水面，光圈一圈圈往外走、边缘最亮，上面一道往上渐隐的淡光柱（`TeleportStations.ts` 的 `pad`）。传送站青色，传送门紫色。不透明是因为加色混合在浅色沙地上会发白、看不出颜色。传送站平台前沿切平，接上圆盘。触发区位置和半径没变；第二、三世界的传送点还是原来的细环。

## 第五步：调光照，柔和明暗、发光物和光晕（2026-10-28）

深色像素原来主要来自三处：结构色改成的胡桃木（桥柱、灯笼框、矿架）在背光面偏黑；树干和树冠下的阴影；桥下水面。原作背光的地方也是暖亮色，阴影很淡。

- **定参数的方法**：在公开版上用 `tools/check-lighting-tone.cjs` 同机位实时切换参数，比了两轮。图在 `artifacts/valley-light/variants-1/` 和 `variants-2/`。
  - 第一轮比了三组：A 轻、B 中、C 是 B 加曝光。
  - 第二轮在 B 的基础上，去掉“地面天光遮蔽减弱”（它会连带地下休整层），再试加曝光。两项都对画面几乎没影响，所以都不改。
- **定下的值**（B1）：
  - 地表补光（`SceneLighting.ts`）：天光强度 0.38 → 0.7，天光色 `#d9e4ea` → `#dfeaf0`，地面反光色从暗橄榄 `#867f5c` 改为暖沙色 `#c4b48a`。背光的墙和树冠下面吃到暖色反光。
  - 烘焙阴影（`bakedLight.ts`）：`shadow` 0.88 → 0.7，阴影里留三成阳光，阴影形状不变；建筑和树的天光遮蔽 `aoBuildings` 0.5 → 0.35。地面的 `ao` 保持 1。
  - 材质提亮（`albedoLift.ts`）：建筑亮度 1.2 → 1.25，背光面暖色反光 3.6 → 5.2；树和岩石亮度 1.22 → 1.28，反光 3.6 → 5。
  - 曝光不变。
  - 测试要求白天阳光至少是补光的 2.5 倍，现在约 2.7。
- **发光色块**：Blender 构建时写出 `src/game/content/pinewind/architecture-glow.json`，记录哪些图集色块自发光、强度多少：
  - 灯笼玻璃 0.8、信标 0.9、熔岩 0.75、三种水晶各 0.3、冰 0.18。
  - 建筑材质按片元所在色块，把自身颜色加到自发光里，在阴影里也是亮的。
  - 最多 12 个色块，打包成 3 个 vec4 常量循环比较，不用动态下标。
- **光晕**：同一个 JSON 里记录每盏灯、信标、熔岩口在所属模型里的位置，一共 15 处。游戏里按模型实例的摆放算出世界坐标，每处画一片朝向镜头的加色柔光片，全部合成一个网格、一次绘制（`SurfaceHalos.ts`）。
- **影响范围**：只有地表。地下休整层不用这几种材质，地面天光遮蔽也没改。
