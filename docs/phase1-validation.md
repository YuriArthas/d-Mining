# P1.V：混合地形与动态矿区验证

本文保留原验证阶段的实现与测量。2026-10-03 已按用户最新要求改为唯一稀疏逻辑源、独立渲染/碰撞系统，旧的 16³ 数组/位图和混合驻留结构已移除，当前实现见 [P2 地形记录](phase2-terrain.md)。

状态：基础实现和自动/浏览器功能验证完成；真实手机性能与手感尚未验收。插入 P1.2 与 P1.3 之间；不改变后续阶段编号。

## 目标与边界

验证 Three.js/R3F + Rapier 胶囊角色控制器 + 自有分块体素系统是否可作为 MVP 基础。逻辑矿区至少 100 × 100 × 2000 格，懒生成；数据、画面与物理分别管理，远处卸载。仅验证基础走跳、普通模型地形、局部挖除与生命周期；不实现商店、矿物经济、宠物、存档 UI 或完整 P1 手感验收。

## 实现决策

- 直接使用 Rapier JS/WASM API，避免逐格或逐帧创建 React 物理组件。
- 物理网格忽略矿物颜色，以相同占用数据单独合并；普通模型使用简化静态碰撞体。
- 体素始终是权威数据；新区块画面、碰撞与挖除修改在主线程同一次提交切换。准备期间保留旧版本。
- 数据按需生成；只维护有限区块窗口和挖除位图，不分配完整 2000 万格数组。
- 验证用深层定位仅在调试接口提供，不作为正式游戏传送/重开功能。
- 真实手机 60 FPS 与手感单独验收，浏览器软件渲染数据不冒充手机性能。

## 完成门槛

自动测试与浏览器证明功能、边界和资源清理；记录主要耗时与局限。验证阶段实现完成不代表 P1.3–P1.6 全部通过。若动态碰撞重建超预算，先缩小更新范围或调整碰撞表示，再扩展玩法。


## 实现结果

- 独立使用 `@dimforge/rapier3d-compat@0.19.3`，WASM 随 JS 本地交付；每个游戏实例一个物理世界，退出释放。
- 圆柱外观配直立胶囊；60 Hz 固定逻辑步长，最高约 60 FPS 的绘制调度。WASD/摇杆移动、空格/按钮跳跃；普通平台、斜坡、台阶和矿区共用碰撞。
- 逻辑范围 X/Z 各 100 格，Y 深度 2000 格。16³ 区块，2m/格；顶层按区域采样，1000 层处有固定测试洞室。
- 数据和渲染请求半径为 2 个区块，距离超过 3 块卸载；单次深层工作集 125 块，保留窗口理论上限 343 块（地图边界会进一步裁剪）。
- 碰撞在 1 块半径内创建，超过 2 块卸载；普通平台离远也卸载物理。有限矿区边界保留 5 个简单静态碰撞体。
- Worker 单任务串行；邻接格 halo 决定边界表面，不将未加载邻块当空气。未修改区块直接按种子生成；修改查询只访问附近 27 个位图，不遍历全世界修改记录。
- 每格编号用 Uint16；每个有挖除的区块分配 512 字节位图。无逐格 React 节点、Mesh 或刚体。
- 渲染合并同类面；碰撞合并时忽略矿物差异。地图数据、视觉和碰撞在受影响区块全部就绪后一起提交，等待期间仍使用旧状态。
- 一次最多一个挖除事务；未完成时不会重复挖除或重复记数。普通加载每帧最多安装一个区块；边界挖除事务可能同帧替换多个区块。
- 当前地区未准备好时停止角色推进，不放任角色掉入未加载区域；提前加载下一步与角色占用的区块。
- 调试入口提供地表/1000 层定位，以及区块、碰撞、数组内存统计；控制台 `window.__miningValidation.snapshot()` 提供队列、卸载计数和耗时样本。普通入口没有该调试接口。
- 本轮修改仅保存在会话内存中；卸载重载仍保留，刷新不保留。正式 IndexedDB 存档属于 P5。

## 验证证据

- `npm test`：15 项通过，覆盖输入、合并网格朝向/面积、材质与碰撞分离、内部面剔除、负坐标与边界、修改重建、Rapier 落地/跳跃/滑墙/坡道/支撑面移除/未知区域冻结及平地稳定性。
- 生产构建通过，包含独立 Worker 资源。当前 JS 约 3.39 MB、gzip 约 1.16 MB，主要增加来自 Rapier/WASM；仍有 bundle 体积提示。
- 本地与公网完整流程：实际键盘移动/跳跃、挖脚下下落、跨区块挖除、1000 层加载、远处物理卸载、修改后往返不复原、淘汰旧 Worker 结果、反复往返后常驻数量有界。
- 本地与最终公网手机浏览器模拟：竖向窗口实际旋转横屏画布、摇杆驱动胶囊、三指操作、转镜头坐标转换、触点取消、通过真实挖掘按钮移除选中格子、方向切换、退出。
- 原 20 次 Canvas/RAF/监听/上下文退出检查通过；另外 5 次等待 Worker 初始化后退出，验证 Worker 终止和所有上述清理。
- 棋盘形 32 次挖除：提交之前数据保持旧状态；提交后格子为空；记录位图仅 512 字节，碰撞体不会随挖掘次数累积。

首轮公网采样（功能检查，非手机性能测试）：

| 场景 | 常驻区块 | 地形碰撞体 | 格子数组 |
| --- | ---: | ---: | ---: |
| 出生地表 | 50 | 12 | 409600 字节，约 0.39 MiB |
| 1000 层洞室 | 125 | 8 | 1024000 字节，约 0.98 MiB |
| 矿区远角 | 32 | 9 | 262144 字节，约 0.25 MiB |
| 多次往返后地表 | 50 | 10 | 409600 字节，约 0.39 MiB |

边界附近保留窗口和已挖表面会使碰撞体数不同；没有要求每次返回恰好恢复相同碰撞体数量。数组统计不含 GPU 副本、Rapier WASM 内存、浏览器及其他资源，不能当作总内存。

证据脚本和 JSON/截图在本地忽略目录 `artifacts/`：`check-validation.cjs`、`check-validation-mobile.cjs`、`check-validation-stress.cjs`、`check-validation-exit.cjs`，以及 `pv-*-report.json` / `pv-*.png`。单元测试随源码交付；浏览器脚本使用相邻项目已有 Playwright，仅为开发验证依赖。

## 发现的问题与下一步

1. Rapier 自动贴地在当前场景产生约 5cm 的平地高度波动。P1.V 已关闭自动贴地，采用扫掠重力；新增 300 步站立回归通过。后续 P1.3 已加入独立胶囊支持面检测、台阶贴地和位置插值，自动/浏览器验证通过；详见 [P1.3 实施记录](phase1.md#13-p13-实施记录2026-10-02)。完整人工手感仍待验证。
2. 挖除等待 Worker 结果后统一生效，存在真实提交延迟。最后一次 640×360 软件浏览器的 32 次棋盘挖除采样中，提交延迟 P95 约 118ms、碰撞体创建 P95 约 0.4ms；此时还有其他浏览器验证负载，不能推导手机预算或归因所有等待时间。已记录 `editLatencyMs`，P2 应按目标设备收敛更新范围与调度；不能因为数据同步正确就称挖掘手感达标。
3. `workerBuildMs`、`colliderCreateMs`、`geometryPrepareMs`、`frameCpuMs`、`mainFrameMs` 为不同边界的耗时；后者包括主线程渲染提交，不等于 GPU 实际执行时间。每项保留最近 256 个样本。
4. P1.V 当时仅有基础相机；后续 P1.4 已实现低顶观察点避障、近裁剪面保护、距离恢复和角色淡出，自动、本地与公网浏览器验证通过。用户手感和实机验收仍待完成；没有镐子模型/摆动和正式开采经济。
5. 所有浏览器验证使用软件 WebGL 与模拟触控；目标手机 60 FPS、热稳定性、总内存和实际触控手感仍未验证。

当前结论：分块懒加载 + Rapier 混合地形方案的功能链路成立，后续 P1.3 也已完成实现和功能验证；性能验收不能据此跳过。

最终公网移动端脚本改为等待实际移动/镜头状态变化，避免用固定 50ms/500ms 假定软件浏览器已绘制；真实三指输入、实际挖除与退出通过，截图已查看。
