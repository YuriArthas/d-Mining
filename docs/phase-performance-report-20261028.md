# 性能上报按钮（2026-10-28）

用户觉得游戏有点卡，要求在左下角加一个小按钮，点一下就把性能统计和浏览器、机型信息上报，走 w-sunjun-public 的域名。

## 用法

- 按钮在左下角，写着“上报性能”（英文 Report performance）。电脑上贴着左下角；触屏设备上在摇杆正上方。
- 按一下，把最近 30 秒的数据发到服务器。按钮会依次显示：
  - 发送中：“正在上报…”，这时按钮不可按；
  - 成功：绿色的“已上报 · 8 位编号”；
  - 失败：红色的“上报失败，点按重试”。
  - 8 秒后恢复原样。
- 只有按了才发送，平时不发任何请求。
- 看报告：`node tools/read-performance-report.mjs [编号前缀]`。不写前缀就读最新一份。它会打印：
  - 设备和 GPU；
  - 帧时间分布；
  - 最近 40 秒每秒一行；
  - 最慢的几个长动画帧，以及其中跑的脚本。

## 报告里有什么（`src/game/presentation/PerformanceRecorder.ts`）

- **逐帧**：最近 1800 个动画帧（60Hz 约 30 秒）。
  - 每帧记录：时间、间隔、更新+提交的主线程耗时、标志位、绘制次数、三角面数。
  - 标志位分三种：画了、到了该画的时候、长停顿。
  - 超过 1 秒的停顿（切后台、断点）算作分段，不算慢帧。
- **每秒一行**：最近 3 分钟。
  - 帧率、最慢一帧、平均和最大 CPU；
  - GPU 没跟上而跳过的次数；
  - 绘制次数、三角面数、JS 堆；
  - 当时所在的场景和坐标。
- **汇总**：
  - 帧率、屏幕刷新率；
  - 帧间隔 p50/p90/p95/p99/最大；
  - 超过 33/50/100/250 ms 的帧数；
  - 更新 CPU 分布、GPU 等待比例；
  - 长任务数和总时长。
- **长任务和长动画帧**（Chromium 才有）：长动画帧会带上耗时最多的 4 段脚本，包括文件、函数和调用方。
- **设备**：
  - UA；
  - `userAgentData` 的高熵信息：Android Chrome 能拿到手机型号，iPhone 和 Safari 拿不到，只能从屏幕尺寸和 DPR 推；
  - 核数、内存、触屏、屏幕和 DPR、视口、网络；
  - WebGL 的 GPU 名称（`WEBGL_debug_renderer_info`）、支持的压缩纹理、计时扩展；
  - WebGPU 适配器信息：Safari 的 WebGL 只写“Apple GPU”，WebGPU 适配器能多给一点。最多等 0.8 秒。
- **画面**：
  - 绘制缓冲尺寸、像素比、MSAA；
  - 上一帧的绘制次数和三角面；
  - 几何、纹理、着色器程序数。
- **游戏**：
  - 世界、深度、是否在传送；
  - 帧率模式、烘焙阴影开关、语言；
  - 启动各阶段耗时、地形流水线的 p95 和最大值。
- **开销**：每帧只写几个 typed array，每秒取一次玩家位置；报告只在按下按钮时才拼。一份报告 30–60 KB。

## 第一份真机报告：电脑（`3c054c0f`）

**机器**：Windows、Chrome 156、RTX 4060 笔记本显卡、16 核、32 GB。屏幕 2560×1440 @1、144 Hz，画布 2406×1309。报告在开局 28 秒时上报。

**平时**：最近 12.5 秒稳定 144 帧，帧间隔 p99 7.1 ms、最大 8 ms，更新 CPU p95 2.1 ms，GPU 等待 0%。这台电脑平时不卡。

**卡的是几次一次性停顿**：

1. **第一次点击卡 316 ms。** 长动画帧记录点名是 `pointerdown` 里的 `unlock`，也就是声音初始化：开音频设备，生成混响和噪声缓冲。服务器上分段计时，第一次 `new AudioContext` 63 ms，混响 36 ms，环境噪声 13 ms；在这台 Windows 上合计 316 ms。第一次按 WASD 也会触发同样的停顿。
2. **站着不动时有一帧 49 ms。** 发生在 15 秒，时间花在游戏自己的帧回调里；同一秒绘制次数从约 100 跳到 150，三角面也随之增加，说明有新东西进入视野。报告里一共 38 个着色器程序，加载时只预热了 23 个。着色器预热原来只覆盖开局镜头视野里的物体，背后的东西要等第一次转过去才编译，而 Windows（ANGLE/D3D11）编译一个程序要几十毫秒。在服务器上转镜头一圈复现：出生点这一圈就有 10 个程序是在游戏中途才编译的，包括传送点水面和光柱、几处水流/发光、标牌、一种标准材质。
3. 开局加载期间还有 107 ms 和 192 ms 两个长任务，发生在加载画面还没消失时，玩家感觉不到。

另外，每秒的 JS 堆在 117–142 MB 之间来回摆，说明每秒要产生约 10–20 MB 垃圾。电脑上没有因此掉帧；手机上可能引起垃圾回收停顿，等手机报告再看。

## 第一轮修复

- **声音提前准备**（`GameAudio.prepare`）：加载时就建好 AudioContext、混音、混响和噪声，处于暂停状态；第一次点击或按键只调用 `resume()`。点击之前仍然不出声。声音和音乐都关掉时不打开音频设备。新增单元测试。公开版上用无头 Chromium 检查：点击之前上下文已经建好，点击时没有长动画帧。无头模式默认允许自动播放，所以点击之前状态显示的是 running；真实浏览器里点击之前是 suspended。
- **着色器全量预热**（`prepareShaders`）：
  - 场景里所有可见的物体都参与预热，不再只预热镜头视野里的。
  - 浏览器支持并行编译（`KHR_parallel_shader_compile`，这台电脑支持）时，先并行编译全部程序，再每 32 个物体一批画一次 1 像素。
  - 不支持并行编译时，同一个程序只取一个物体编译并画一次。判断是不是同一个程序，用材质类型、着色器、贴图槽、透明等组成的键近似 three 的程序缓存键。
  - 第一版直接按材质逐个预热：301 个物体在服务器上要 4–5 秒，太慢，改成现在这样。
  - 公开版服务器测量：加载期间预热 32 个程序，耗时 2.1 秒（SwiftShader 软件编译，平均每个约 66 ms；真显卡快得多）。转镜头一圈后，游戏中途只剩 2 个程序编译，是新手引导箭头：加载时它是隐藏的，只在新档第一次出现时编译一次。
- 全量测试 507 项通过。

## 手机报告（`de0bf547`）和第二轮修复

**手机**：iPhone，iOS 26.6，Edge。屏幕 390×844@3；苹果不报告型号，这个尺寸是 iPhone 12/13/14 一档。竖着拿手机，游戏转成横屏，可用区域 604×390，绘制缓冲 906×585（像素比 1.5）。这份报告跑的是已含第一轮修复的版本。

**表现**：全程 60 帧，帧间隔 p50 17 ms、p95 18 ms、p99 24 ms、最大 50 ms，CPU 每帧 3–4 ms。30 秒里有 15 帧错过一次刷新，其中 13 帧发生在矿坑附近；那里绘制次数是 180–185 次，地面上是 81–133 次。加载预热 32 个程序，耗时 365 ms（iPhone 支持并行编译）。iPhone 不提供显卡计时，也不报告长任务。

**蛋上方的名称和价格牌按世界分批**（`EggStandLabels`）：
- 原来三个世界 29 颗蛋的牌子合成一批，包围球半径 245 米，从不被视锥剔除。世界 1 只要蛋台进入视野，就要把全部牌子画一遍：12.7 万个三角形，占这类画面的一半。
- 现在每个世界一批，包围球半径 10–17 米；两批共用同一套材质，不增加着色器程序。
- 字的曲线分段从 5 降到 3（`EGG_LABEL.curveSegments`），总量从 12.7 万降到 8.9 万：世界 1 约 2 万，世界 2 约 3.6 万，世界 3 约 3.3 万。实际大小下看不出棱角。
- 公开版同机位每帧三角形：出生点看矿井 31.9 万 → 21.1 万，广场朝西 23.7 万 → 12.9 万，广场朝东 25.0 万 → 12.2 万；正对蛋台时 9.9 万，其中牌子 2.1 万。

**隐藏但会用到的东西也预热**（`prepareShaders` 的 `userData.prewarm`）：
- 新手引导箭头加载时是隐藏的。
- 裂纹覆盖层要等第一次敲方块才创建；现在 `BlockCracks` 多带一个隐藏的占位覆盖层，用的是同一份材质。
- 公开版服务器复测：加载后转一圈、进矿坑、挖四块，游戏中途编译 0 个程序（之前是 3 个）。加载预热 35 个程序，约 2.1 秒（SwiftShader）。
- 裂纹测试改成只数真正的覆盖层，不数占位。注意：这一版是在这 3 项测试失败的情况下发布的，测试是发布之后才修好的；代码本身没有再改。

**上报按钮防连按**：第二下点击可能赶在 React 把按钮重新渲染成禁用之前，公开检查就出过一次连按存了两份。现在点下去的瞬间就用 ref 同步上锁。公开检查四项全过。

**为查矿坑掉帧准备的数据**：每秒一行里新增 `slow`（这一秒内错过刷新的帧数，即帧间隔超过 25 ms 的帧）和 `probe`（调试面板“性能诊断”当前的对照模式）。`read-performance-report.mjs` 会按模式汇总每秒平均错过几帧。

全量 508 项通过。
