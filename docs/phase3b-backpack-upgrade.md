## 范围与操作

HUD 的“升级背包”按钮随时打开界面，显示当前容量、下一档容量、持有金币及费用。金币不足显示差额，达到最高档后禁用购买。支持关闭按钮与 Escape；界面内操作不穿透到角色移动、转镜头和挖掘。关闭恢复输入。地形计算和已接受采集仍可完成，不增加暂停流程。

临时配置：初始容量 50；100 / 200 / 400 容量的升级价格分别为 20 / 50 / 100 金币。配置独立放在 `application/BackpackUpgrade.ts`，不做数值平衡。售价仍为所有矿物 1 金币，存档仍后置。

## 模块边界

- Inventory 新增 `setCapacity(value)`，只更新容量和派生快照。降低容量也不删除已有物品；`add(items)` 始终不受容量限制。
- BackpackUpgrade 独立查询下一档、检查目标档位与购买条件、扣金币并调用容量 API。依赖库存/钱包的窄接口，不知道地形、角色、圆圈或 UI。
- 下一档由当前容量与固定配置计算，不另存一份可能失配的背包等级。
- 购买命令携带展示的档位 ID，重复提交旧 ID 不重复扣款，也不自动购买下一档。未购买成功不修改余额和容量。
- GameSession 只在完整购买结束后发布一致快照；UI 订阅报价并发送购买命令，不直接修改金币、容量或矿物。
- 界面的打开状态归 App/UI，输入接线在打开时清理并卸下、关闭时恢复；不把 UI 状态放入库存或升级规则。
- GameButton 对非主触点处理松手操作，并抑制随后合成的兼容 click，避免一次触摸购买两档。
