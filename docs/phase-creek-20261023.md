# 小河重做：下沉河道、水面着色、河岸点缀（2026-10-23）

用户说“那条小河，得改改，现在太 low 了”。原来的小河是平铺在草地上的一条青色带子：河床 0.01 米、岸 0.02–0.04 米，水面 0.055 米，等于贴在地上；水是一张 64 像素、带几块亮色方块的哑光贴图，没有深度、没有河岸、没有水的质感。工作区 `/root/.t3/worktrees/d-Mining/surface-roblox`，基于 `c918c13`。

## 为什么要碰体素世界

地表下面有一层体素地面：矿井口以外，`y = -1` 格（-2 到 0 米）处处是不可挖的保护层，既是碰撞，也会在玩家附近被渲染出来（只是被地形盖住）。所以只把地形的河床往下挖，看到的是体素顶面，人也会被隐形地面托在 0 米、像站在水面上。

做法：只在**体素网格生成**（渲染和碰撞）里把河道下那一层当成空的（`WorldGeneration.surfaceCut`，`src/game/terrain/meshing.ts`）。玩法数据不变：这些格子仍是保护层，所以
- 生成版本号不变（还是 11），存档照常读取；
- 站在河里选不中、挖不到河床下面的方块；
- 河床和河岸靠地形自己的碰撞体托住人。

镂空格子由小河形状算出（`pinewindSurface.ts` 的 `creekFloorCells`，715 格），小河形状本身移到 `hubLayout.ts` 的 `PINEWIND_CREEK`，地形脚本经 `layout.json` 读同一份。游戏改用 `PINEWIND_GENERATION`（`App.tsx`）。

## 改了什么

- **河道断面**（`landscape.ts`）：草地边缘先是一道草皮翻边，然后是约 40° 的土坡（人能走上走下），在水线处（-0.40 米，比草地低约 0.4 米）入水，水下继续到中心约 -0.95 米的河床。露出水面的河岸是土色，水下的河床颜色更深。
- **水面**：按横向 6 列的条带网格重建，带 `_creek` 属性（横向 0–1、顺流米数）。游戏里的着色器（`src/game/presentation/creekWater.ts`）在标准材质上画：岸边浅青、河心深蓝的渐变，顺流漂动的宽水纹和零星闪光，两岸断续、边缘晃动的白沫；粗糙度 0.22，斜看时能映出天空，桥和河岸的烘焙阴影照常落在水上。
- **河岸点缀**（`creekDressing`，单独的随机序列，不影响其它摆放）：水线上半浸在水里的圆石、岸边芦苇丛、靠岸处 7 簇睡莲叶。
- **桥墩**往下延伸到河床（-1.1 米），不再悬在河岸坡上。
- **站在河里算地表**：原来“脚高于 -0.1 米才算地表”，站进河里会被当成进矿（冒出挖矿提示、不能传送等）。现在河道格子内、脚高于 -1.2 米也算地表（`SessionContent.sunkenSurface`）。体素地面只在 0、-2、-4 米这些高度，-0.1 到 -2 米之间唯一能站人的就是河床，不会误判。注意：旅程模式下脚低于 -1 米且矿区未开放会被送回出生点；河床上脚底是 -0.92 米左右，第一世界矿区默认开放。
- **蹚水脚步声**：新增 `water`（溅水加两下水滴，程序合成）；脚在水面以下是水声，河岸坡上是泥土声。
- **删掉**旧的水面贴图函数。

## 中间遇到的问题

- 第一版水面全是沿水流方向的细白线。先以为是 `sin` 散列在大坐标下丢精度（确实是隐患，已改成不用 `sin` 的散列并把格点折回 0–288），但用 JS 把公式原样画一遍发现细线还在：真正原因是让流速随横向位置变化，时间乘上随位置变化的速度后，相邻像素列的顺流相位相差很大，图案被撕成细线，而且时间越久越严重。改成每层固定流速。
