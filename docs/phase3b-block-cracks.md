# P3B.3：方块受损裂痕

按用户要求加入类似 Minecraft 的像素裂痕表现，与方块损失血量的比例挂钩。整体难度 30/100。

## 行为

- 完好方块不显示裂痕；按 `(最大 HP − 剩余 HP) / 最大 HP` 分为 10 档，伤害越重，裂痕向外扩展并加粗。不同矿物按各自最大血量计算，不按敲击次数累计。
- 切换目标、松手后，受损方块的裂痕仍保留；切换区域卸载其渲染资源，回来后根据保留的伤害恢复。
- 归零到实际删除之间显示最终裂痕；实际删除后移除。伤害、销毁时序、入包和冷却规则沿用 P3B.2。

## 模块与性能

- `BlockHealth.observe` 只提供稀疏伤害回放、变更通知和取消订阅，不知道图案、材质或地形。
- `GameSession.observeBlockDamage` 把逻辑键转换为坐标及 HP/最大 HP，只暴露只读数据。
- `presentation/BlockCracks.ts` 是可丢弃的表现缓存，独立建立受损格子的稀疏区域索引。同一区域采用 InstancedMesh 批量画受损方块表面，不为每个方块创建 Mesh。
- 一张程序生成的原创像素图集，10 档共 40 KiB；所有区域共用材质和纹理，不引入外部素材。
- 表面覆盖使用深度检测与 polygon offset 避免共面闪烁，不修改原来的矿物材质、合并地形或任何碰撞体。受损方块的六面共用当前裂痕档位，新暴露的侧面自然显示。
- 每帧仅检查已加载渲染区域；档位变化或区域重新加载时才上传实例数据，闲置不重建/上传。实例容量按需要翻倍，仅在有受损方块的已加载区域分配 GPU 缓存。区域卸载、最后一个受损格子删除、场景退出时释放对应资源。
- 一般代价为每个有裂痕的可见区域一个额外 draw call、每个受损方块 12 个三角形；不预分配完整矿区或逻辑 16³ 数组。真实手机性能需要实机验证。

## 验证

- 107/107 Node 测试通过，新增覆盖 10 档比例、图案逐档保留并增长、伤害通知、区域批绘制、闲置零上传、远处无 GPU 分配、负坐标/深处、卸载恢复、销毁与退订清理。
- 类型检查和生产构建通过。
- 本地与公网浏览器检查通过：1120×630 电脑、844×390 手机横屏、390×844 旋转横屏。公网使用鼠标点击/触摸长按触发首击，观察 10%/50%/90% 伤害、两个目标独立显示、远行卸载恢复、挖碎清除；页面/着色器/资源错误为 0。
- 对比扣血前后，地形三角形数、碰撞三角形数、地形区域网格数和实际挖除数均不变；闲置时裂痕上传计数不增加。证据：`artifacts/cracks-local-report.json`、`artifacts/cracks-public-report.json`；已查看电脑和手机裂痕截图。
- 已发布原 Mining 地址，仅更新对应子目录，保留旧资源并原子替换入口，公网 HTML 与本地产物一致；当前 JS `index-TjhfF78E.js`。
- 以上为浏览器模拟验证，不替代真实手机 60 FPS 验收。
