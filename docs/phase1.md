# P1：移动、相机与操作参数

状态：2026-10-03，简化版 P1.1 与 P1.2 已实现；新增 P1.V 已完成基础实现与功能验证，P1.3 已完成实现和自动/浏览器验证；P1.4 相机已实现并通过自动、本地与公网浏览器检查；P1.5 选格已完善，几何镐子与 P1.6 待实施。用户最新要求优先挖坑，已提前实施 [稀疏地形与独立渲染/碰撞](phase2-terrain.md)，镐子表现后移。浏览器自动检查通过，真实手机操作与性能尚未验证。

本轮按用户要求简化 P1.1，并实施到 P1.2。原 P0.5 的参数整理已并入本阶段，随实际功能加入；P0.6 保持取消。仅保留退出，不引入暂停、继续、重开或专门的后台处理。

用户已确认增加 [P1.V 混合地形与动态矿区验证](phase1-validation.md)，此阶段的基础实现与功能验证已完成。P1.3 的物理方案改为 Rapier 胶囊控制器；P1.V 提前验证少量挖除与流式加载，原先纯静态/自写网格碰撞的建议由本决定替代。

## 1. 阶段结果与边界

P1 完成后，玩家可以在一个小型静态测试场地中控制圆柱主角，自由移动、转镜头、跳跃，指向面前或脚下的方块并挥动拼装镐子。电脑与手机使用同一套动作语义，操作参数有明确的调整位置。

P1 验证“人物、相机、输入能否共同工作”，不结算矿物、背包、金币或宠物。新增 P1.V 提前接入技术性挖除、懒分块、Worker 和动态碰撞；正式矿区内容与目标手机性能仍在 P2。

本文件中的按键、碰撞算法和尺寸为首轮实现建议，不是用户已经逐项确认的额外玩法要求。相机与触控手感必须通过实际操作收敛。

## 2. 子任务与依赖

难度分为低、中、中高、高；描述的是实现和调试风险，不是工期承诺。

| 子项 | 交付 | 前置 | 难度 | 通过条件 |
| --- | --- | --- | --- | --- |
| P1.1 静态场地与尺寸基线 | 圆柱、朝向标记、简化静态网格、最小配置入口 | P0 现有入口 | 低 | 地图数据、画面和实体查询一致；角色/矿格/通道尺寸可调 |
| P1.2 双端输入与基础视角 | 键鼠、触屏摇杆/视角/动作输入，简单跟随相机 | P1.1 | 中高 | 电脑和手机浏览器可同时产生移动、观察、跳跃、挥镐动作；UI 不串操作 |
| P1.V 混合地形验证 | Rapier 胶囊、普通地形、局部挖除、懒加载/卸载 | P1.2 | 高 | 详见独立验证文档；不冒充手机 60 FPS 验收 |
| P1.3 移动、跳跃与碰撞 | 固定步长控制器、重力、落地、墙面滑动、帧调度 | P1.1、P1.2 | 高 | 转角、窄道、顶头、高处下落与帧间隔变化时无穿墙穿地、异常加速 |
| P1.4 地下第三人称相机 | 镜头避障、距离恢复、俯仰与角色遮挡处理 | P1.3 | 高 | 通道、低顶、转角和竖井可看清方向与脚下，镜头无明显穿透或抖动 |
| P1.5 目标选择与挥镐 | 网格选中、高亮、距离检查、几何镐子摆动 | P1.3、P1.4 | 中 | 指向正确矿格，不能超距选择；挥动不锁移动和镜头，不改地形 |

建议实施顺序：P1.1 → P1.2 → P1.V → P1.3 → P1.4 → P1.5 → P1.6。

这不是一次做完后才看效果的瀑布流程：P1.2 后即可看双端输入，P1.3 后即可试玩移动；P1.4 和 P1.5 之间允许围绕实际瞄准手感小幅迭代，不等 P1.6 才第一次用手机。

## 3. P1.1：静态场地与尺寸基线

### 工作

- 在现有独立游戏入口内建立一张小型、有限边界的静态测试地图。
- 主角使用圆柱，加一个简单朝向标记，避免对称圆柱让人分不清朝向。
- 本轮仅做 14 × 14 格地板和 5 块组成的小转角，共 201 格，用一个 InstancedMesh 绘制。
- 窄道、低顶、阶梯、竖井等专项场景随 P1.3/P1.4 加入，不先搭完整测试路线。
- 地图用一份网格占用数据描述；画面和碰撞查询读取同一来源。
- 提供最小的整数格状态查询，区分实体、可通行空格和不可进入区域；为 P2 保留“尚不可用”语义，不能把未加载区域当空气。P2 的分块存储实现相同查询语义。
- 测试地图可用一个或少量 InstancedMesh 表现固定方块，不提前实现 P2 的分块网格系统，也不为每格创建 React 组件。

### 参数

建立小型 TypeScript 配置文件，先只包含已经使用的矿格尺寸、角色尺寸、出生点等；后续子项加入自己的参数。若背景色同时用于 CSS 和 Three.js，也在此阶段统一来源，不另开独立配置工程。

初始尺度要留出第三人称观察空间。具体米数通过通道试走和镜头试验确定，不预先把一格通道做得刚好贴住角色。

### 验收

- 改尺寸或出生点并重建后，画面与查询结果一起变化。
- 地图没有单独维护的视觉墙和碰撞墙两份数据。
- 基础场地足以观察尺寸、朝向和旋转镜头；本阶段不要求覆盖全部碰撞路线。

## 4. P1.2：双端输入与基础视角

### 工作

- 输入输出统一为移动向量、观察增量、跳跃触发、挥镐按住状态；适配器不直接修改角色坐标。
- 电脑首轮建议：WASD 移动、空格跳跃、按住右键拖动转镜头、左键按住挥镐。画布内处理右键菜单，普通 UI 保留正常点击。
- 首轮不把 Pointer Lock 当作必需条件，减少首次点击、浏览器捕获和退出操作之间的耦合；试玩后若需要再讨论。
- 手机：左摇杆、跳跃按钮、场景触点长按挖掘/拖动观察，每个触点按 pointerId 明确归属。
- 保持一个触点从按下到释放的归属；移出起始控件仍由原控件持有，不误交给观察区。抬起、pointer cancel 或丢失指针捕获时结束对应动作。
- 按用户确认，借鉴 Minecraft 的直接触点操作：按住约 180ms 挖掘，此前拖动超过 10px 则观察；一旦进入挖掘，滑动只换目标。左手可独立移动，镜头调整需结束本次挖掘手势。
- 手机触点处提供提示圈，格子高亮表达实际有效目标；不保留中心准星或独立挥镐按钮。
- 建立简单后上方跟随视角，并允许 yaw/pitch 调整，供 P1.3 验证“相对相机方向移动”。此时不把未完成的相机避障标为通过。
- UI 的退出、摇杆、动作按钮各自消费输入，不能穿透触发场景操作。

### 验收

- 键鼠和触控产生相同语义；方向输入归一化，斜向不会提供更大输入长度。
- 多指同时操作、触点越界和取消时不串指、不粘住挥镐或移动。
- 退出按钮始终可点击；不显示旋转提醒或按方向禁用输入，不新增暂停或恢复确认。
- 输入清理仅处理正常指针生命周期和退出，不扩展成用户已取消的后台状态管理。

## 5. P1.3：移动、跳跃与碰撞

### 工作

- 按碰撞验证需要补充直墙、窄道、台阶、低顶与有底竖井；下落路线留可跳回的路径，不用自动传送掩盖错误。
- 角色状态保存在普通 TypeScript 对象中；固定逻辑步长推进，画面位置可插值，不逐帧更新整棵 React 树。
- 移动方向取相机水平朝向，俯仰不能让角色朝地面加速或飞起；角色朝向与镜头朝向分开。
- 支持重力、落地判定、起跳、顶头停止上升、碰墙滑动。
- 沿用 P1.V 的 Rapier 胶囊运动学控制器，完善普通模型地形、坡道、小台阶与体素矿区交界。
- 小障碍自动跨越，整格高台靠跳跃；不实现攀爬、蹲伏或通用动态机关。
- 收敛下坡贴地与镜头跟随；P1.V 因平地抖动禁用了 Rapier 自动贴地，需要在本阶段有针对性地完善。
- 为累计时间与每帧逻辑步数设置上限，防止异常长帧触发无界补算。此为时间步长数值约束，不添加后台暂停/恢复状态。
- 使用一个明确的帧调度入口，渲染上限 60 FPS；固定逻辑步长与实际绘制次数分开，高刷设备不每个 RAF 都无上限绘制。
- 退出后取消新增循环与输入监听，沿用 P0 已验证的 Canvas 卸载流程。

### 验收

- 相同输入在不同模拟帧间隔下移动距离基本一致，斜向速度正确。
- 直墙、墙角、相邻方块接缝、跳跃顶头、台阶边缘、从高处落到薄地板等场景无穿透。
- 跳跃输入按触发边沿消费，按住不会误变无限自动跳跃；离地时不能再次起跳。
- 60/90/120 Hz 条件下检查渲染节奏与逻辑速度；模拟检查不冒充实际高刷设备证据。
- 不引入掉落死亡、自动重开等新玩法。

## 6. P1.4：地下第三人称相机

### 工作

- 相机跟随目标点与角色实际位置分开，目标点高度、距离、俯仰范围可以调整。
- 手动转镜头立即响应，跟随平滑使用与帧率无关的方式；默认不擅自把水平朝向转回角色前方。
- 从跟随目标到期望镜头位置检测遮挡，包含近裁剪面所需余量，不只测一个容易穿墙的中心点。
- 遇到墙壁快速收近，离开后平滑拉远；先约束最终位置，避免平滑过程本身穿过墙角。
- 验证低顶与墙角同时约束视线、向下俯视脚下、落入竖井时的镜头表现。
- 通过角色与矿格尺度、观察目标点和近距离遮挡处理看清前方；必要时仅隐藏贴近镜头的占位角色部分，避免强迫玩家看圆柱内部。
- 使用附近已加载的 Rapier 碰撞体进行相机形状查询，覆盖普通地形与矿区；与矿区视觉更新保持一致。

### 验收

- 进出窄道、背靠墙旋转、低顶跳跃、沿竖井下落，镜头不明显穿墙、弹跳或持续抖动。
- 可以看见脚下的目标区域；输入灵敏度不会随设备像素比改变。
- 最小镜头距离只是期望限制，不能为了满足这个数值把相机放进实体；极窄处允许进一步收近并处理角色遮挡。
- 第一轮人工操作明确反馈“可用/不舒服的场景”，不能用几张截图代替手感结论。

## 7. P1.5：目标选择与挥镐

选格部分已实现，按最新优先级接入 P2 的真实挖除；主角和几何镐子动作按用户最新要求允许跳过，当前转向多矿物外观与合并验证。规则与本轮证据见 [选格修正](phase2-terrain.md#选格修正2026-10-03)。

### 工作

- 电脑按鼠标位置，手机按长按触点；从当前帧相机沿逻辑网格查询第一个可见实体，返回整数格坐标与命中位置。
- 再检查角色到命中表面的触达距离（当前 4 格 / 8 米）；不增加角色到目标的遮挡检查。
- 高亮当前有效目标；无目标或超出距离时清除，移动和转镜头时及时更新。
- 用几何体拼出镐柄和镐头，挂在圆柱侧面，按住挥镐时往复摆动，释放后恢复静止。
- 有效目标与开采意图已接入提前实施的 P2 挖除；本阶段不引入矿块生命、物品或经济。
- 镐子挥动是表现，不以挥动动画帧直接决定以后每次扣血的规则时点。

### 验收

- 正面、脚下、墙角、边界上的目标明确；超距、指向空气时不选中错误方块。
- 可以同时移动、转镜头和挥镐；动作不锁角色或改变玩家镜头。
- 切换目标后高亮立即跟随；高亮与挖除使用同一个有效目标。

## 8. P1.6：联调与验收

- 走完整测试路线：平地移动 → 跳台阶 → 窄道转弯 → 低顶 → 竖井下落 → 指向脚下/前方 → 挥镐 → 退出。
- 自动检查重点放在移动/碰撞边界、目标距离、多指归属、退出资源释放；不为每个样式或常量写镜像测试。
- 手机摇杆、观察区与动作按钮避开安全区域，退出入口保持可达。
- 调整实际操作参数并记录单位、范围和读取位置，验证修改配置后确实影响角色/相机。
- 发布当前阶段版本到现有 Mining 入口后再复核实际页面；不靠旧产物证明新代码通过。
- 在电脑和目标手机做实际操作，收集镜头与触控反馈。没有真机证据时单列未验证项，不把 P1 整体标为验收通过。
- 静态场地也以手机 60 FPS 为目标，观察移动与转镜头期间的帧耗时；这仅是 P1 基线，正式矿坑负载仍在 P2 验证。
- 回归退出时新增的帧循环、输入监听、几何与材质释放；不把一次退出成功当作长期内存稳定结论。

## 9. P0.5 迁移后的配置规则

本项是贯穿 P1.1–P1.6 的交付要求，不再单独安排一个“先建配置系统”的子阶段。

| 参数组 | 例子 | 首次引入 |
| --- | --- | --- |
| 场地和角色尺寸 | 格子边长、角色宽高、出生位置 | P1.1 |
| 输入 | 摇杆半径、死区、鼠标/触屏灵敏度 | P1.2 |
| 移动 | 速度、重力、跳跃高度或初速度、逻辑步长 | P1.3 |
| 相机 | 跟随目标高度、距离、俯仰范围、收近/恢复参数 | P1.2 起，P1.4 完善 |
| 目标和工具表现 | 触达距离、镐子摆幅、摆动周期 | P1.5 |

配置仅用普通 TypeScript 数据直接导入；避免重复表达同一事实，例如跳跃高度和起跳速度不能同时作为互不相关的权威值。配置与逻辑实际读取位置可定位，单位与有效范围写在旁边。矿物、售价、掉落、宠物配置留到对应阶段。

## 10. 自复核结论

拆分后按依赖、体验、复用、验收与范围检查了一遍，修正了以下问题：

| 初始拆分容易出现的问题 | 本计划的处理 |
| --- | --- |
| 先做移动，最后才做手机输入 | P1.2 就接双端动作，后续控制器共用输入；手机手感不押到最后 |
| 没有相机却要求相对视角移动 | P1.2 提供基础视角，P1.4 才完善地下避障，解除依赖循环 |
| P1 临时 Mesh 碰撞，P2 又换一套体素碰撞 | 静态地图也从网格占用数据查询；P2 替换存储与更新实现，保留查询语义 |
| 相机舒服被拆成单纯数学跟随 | 尺度、近裁剪面、墙角、低顶、脚下视野与双端输入共同验收 |
| 手机左手移动、右手看向后无手操作挥镐 | 现采用直接长按目标；一次手势锁定挖掘或观察用途，左手独立移动 |
| 一边要求按钮上拖动观察，一边规定移出按钮就停止动作 | 明确触点持有到抬起/取消；越过控件边界不会改变归属 |
| 网格只返回实体/空气，无法表达 P2 尚未加载区域 | 最小查询保留不可进入/尚不可用语义，不把未知区域作为空气 |
| 验证下落后必须依赖 P3 返回地表才能脱困 | P1 静态路线自带可跳回路径，不提前实现返回功能 |
| P1、P2 重复实现选矿 | P1 完成目标选择与意图，P2 直接接入挖掘伤害和地形事务 |
| 为少量常量建立通用配置或控制器框架 | P0.5 分散落实到消费者出现时，不单独搭配置系统 |
| 把简单场景 60 FPS 当成矿坑性能达标 | P1/P2 两套负载分别记录，真实手机证据保持独立 |
| 静态场地通过就宣称动态挖掘正确 | 挖掉脚下方块、异步重建和碰撞同步明确留在 P2 验证 |
| 以防输入残留为由重新加暂停/后台流程 | 只做指针结束、取消与退出清理，不扩大用户明确删去的范围 |

结论：拆分合理，可以按顺序落地。主要返工风险集中在 P1.3 与 P1.4 的接触边界和手感，而不是几何占位模型。P1.2 和 P1.5 在手机操作上需要一起复核，不能只按桌面鼠标操作验收。

## 11. 难度与估算边界

- **整体：中高难度。** 做出圆柱能走、镜头能转不难；同时保证狭窄空间、脚下瞄准、触屏操作和后续地形复用，需要多轮实操调整。
- **最高风险：P1.3 碰撞、P1.4 相机。** 高频返工来自墙角、顶头、近距离遮挡、下落和不同帧间隔，不是写完主路径就结束。
- **中高风险：P1.2 与 P1.6。** 多指归属可以自动检查，拇指舒适区与灵敏度仍需要真实手机操作。
- **相对可控：P1.1 与 P1.5。** 前者是小型静态数据和占位几何；后者在网格查询明确后实现高亮和摆动，但仍需验证视线与角色触达差异。
- 当前不报精确工期。开发与自动检查的工作量较可控，主要不确定性是相机/触控反馈轮次、碰撞体方案是否需要调整，以及目标手机验证条件。

P1 结束时应交付一个能实际操作的测试版本、参数说明、正确性检查和明确的手感/设备记录；不能只交一套抽象代码结构。

## 13. P1.3 实施记录（2026-10-02）

状态：实现、自动测试、本地与公网浏览器检查通过。真实设备性能和人工手感仍未验收。

### 已实现

- 保留 Rapier 胶囊控制器与混合地形，逻辑固定 60 Hz；30/60/90/120 Hz 输入帧间隔下移动距离一致，斜向归一化、移动相对相机水平朝向。
- 每帧最多消化 100ms / 6 个逻辑步，超额时间舍弃并记录；不会为追帧无限补算。高刷屏按截止时间平均调度 60 次绘制，90 Hz 不会退化成固定每两帧绘制的 45 FPS。
- 圆柱和基础跟随目标使用逻辑位置插值；角色朝向指数平滑，转镜头不强迫角色转身。定位后重置插值，不从旧坐标滑过地图。

## 14. P1.4 实施记录（2026-10-03）

状态：相机实现、自动测试、本地与公网浏览器验证通过。人工手感、目标手机性能不据此标为通过。

### 实现与设计取舍

- `src/game/ThirdPersonCamera.ts` 独立维护相机观察点、方向和距离；读取 P1.3 插值后的角色位置。水平跟随直接采用插值位置，垂直跟随指数平滑，最多滞后 0.4m；调试定位清除旧观察点。
- 观察点从角色胶囊内部向上扫掠得到，期望高度为脚底上方 1.9m；低顶会降低观察点，避免跳跃时把观察点放入天花板。
- 球形查询包住相机近裁剪面的四角，半径随横屏宽高比计算，通常为 0.18m。极宽窗口降低 near 来保持检测球能放进角色周围空间；不会只检查中心射线。
- 遇障碍立即收近，腾出空间后按指数曲线恢复到 7.5m。不强制最小距离，平滑只作用于距离；每帧先在当前观察方向求安全距离，再限制最终位置，避免相机的世界位置插值穿过墙角。
- 贴近角色时按距离淡出圆柱和朝向标记，最窄处完全隐藏；地形保持不透明。镜头距离降到零时仍保持玩家指定方向，不用零长度 lookAt。
- 俯仰扩大到 -0.55～1.45 弧度（约向上 32°、向下 83°），允许从井底向上看和接近垂直观察脚下。转镜头不自动归中，不改变角色朝向。
- 相机和角色共用附近 Rapier 普通/体素碰撞体，保持现有加载、挖除和卸载流程。生产每帧两次球形查询；debug 快照额外提供障碍审计，只用于验证。
- 参数在 `src/game/config.ts` 的 `camera` 中，包含 near、检测球大小/余量、观察高度、跟随和距离恢复速度、垂直滞后、角色显隐距离。
