# 光照材质样板：夜景对照 Phase

日期：2026-10-20。样板位于 `light-study/`，公开入口：[光照材质样板](https://w-sunjun-public.dev.clock-p.com/games/mining-light/index.html?light=night&study=both)（已在公开列表中）。本文记录夜景对照的实施与审看；游戏本体（`/games/mining-test/`、正式 `/games/mining/`）不在本轮范围内。

## 背景

用户对比参考视频后认为夜景仍有差距。我与 Claude peer 分别审看，结论一致：

1. 最大差距是**光照主次**：参考里暖灯照亮灯下一片地面，周围迅速变暗；上一版为了“处处看清”，月光照亮了大部分地面，暖灯只是点缀。
2. 其次是**材质响应**：石板块与块差异小、反光弱；墙面只有均匀细纹，缺少大中尺度的灰泥变化。
3. 灯位置与发光感：灯紧贴蓝墙，光集中在墙上；灯芯、小范围光晕和前景遮挡较弱。

视频只能证明视觉差异，不能证明参考用了某种 GI/光追/特定 shader，也没有证据表明差距来自 WebGPU。

## 已完成（本轮首版）

- 固定机位四组对照：原版 / 只改光 / 只改材质 / 一起改，可在公开页底部切换；另有墙、地面、背面三个检查视角。
- 光：灯向前移并配新支架，暖光落到地面；月光减弱，周围转暗。
- 材质：石板在同一表面内区分较干、较粗糙、略有光泽的区域；墙面增加较大尺度的灰泥变化。
- 公开检查通过：`light-study/artifacts/comparison-first-check.log`，截图在 `light-study/artifacts/comparison-first/`（01～07 + `report.json`）。

### 对“一起改”截图的目测结论

对照 `01-courtyard-baseline` 与 `04-courtyard-both`：

- 灯下成为明确的视觉中心，周围深暗，石板的局部光泽在灯下可读，方向对了。
- 灯下以外的地面和右侧蓝墙偏暗，右下角几乎看不清细节；需要保留一点冷色暗部层次。
- 蓝绿墙面的灰泥斑块偏大、偏“发霉/迷彩”，略显花；需要降低对比、让斑块更接近成片厚薄变化。
- 软件渲染截图不能代表用户机器上的亮度和帧率。

## L5：灯体尺寸与柔和柱影（用户后续反馈）

- 用灯罩 0.44 m 宽度对应的 0.22 m 发光半径做点灯 PCSS。24 次搜索遮挡距离、最多 48 次比较过滤，半影随遮挡与接收面的间距增大；接触处仍紧致。它是有限尺寸阴影近似，点灯照明和高光模型未替换成完整面光源。

- 原版、同灯硬影、AO 恢复、昼夜恢复、分段同机位共五组逐像素一致性检查通过；源码/构建/公开/浏览器哈希一致。909 个范围外源码文件、1116 个其他游戏发布文件及模型/贴图资源未变。

## L8：夜景的结构性 GPU 成本（用户笔记本反馈）

用户指出 15–16 ms 的 GPU 耗时不可接受，应检查重大设计错误。逐通道计时和有效软/硬影对照确认：前版只缓存阴影深度图，三盏固定灯仍在每个受影响片元上逐帧做 24 次遮挡搜索与最多 48 次柔影过滤。街景扩大后，这成为主要成本。

- 默认公开街景改用预制静态遮挡图集，每灯一通道；灯色、强度、材质高光、AO、光晕和太阳/月光仍实时计算。保留 `?shadows=live` 原实时对照。
- 新增全局 UV1，117,156 三角面、原位置/法线/材质 UV 全部保留，未裁减或按距离卸载场景。图集 1.84 MB 下载、64 MiB GPU 纹理；来源、依赖与重制条件均有记录。
- 同一软件 GPU、最终模型、1440×900、DPR1，各三次暖帧中位数：21134.15 → 8138.69 ms，下降 61.49%。该结果不能换算成用户笔记本 GPU 的预计毫秒数。
- 公开三机位夜景对照保留柔影与材质响应；三个白天机位与 L7 逐像素不变。日夜、AO、拖动/缩放恢复逐像素一致；页面/WGSL 错误和警告为零。
- 性能栏新增实际渲染分辨率、DPR、阴影模式和分通道耗时，打开时取当前视角暖帧。
- 修正了调试软/硬开关的 uniform group 更新问题；初次关 AO 后的硬影诊断无效，已保留并明确作废。舍弃了收益不足且有无效路径的 depth-reuse 试验，代码已全部移除。
- 2,906 个范围外工作区文件、1,116 个其他游戏发布文件未变。没有移植到游戏本体；动态角色/移动遮挡物未纳入本次验证。

## L29：半分辨率双向光晕、Node 注册表修复与分项上报

按用户“继续”，将垂直光晕滤波从最终全分辨率输出移回半分辨率目标；该方向滤波覆盖像素约减至 1/4，最终输出读取完成的光晕。默认夜景为 **4 passes**，白天保留 AO 为 **8 passes**。保持光晕核/强度、全部 642,264 面、完整材质、4× MSAA、原 DPR 与静态逐帧渲染；多一次半分辨率写回的净性能收益仍需实机数据。

完整切换测试进一步发现原烘焙光节点混用了 `three/src` 与 `three/webgpu` 两套 Node 注册表。最小复现确认源码版 IrradianceNode 与包内 π 常量可共享 ID/hash `63`，NodeBuilder 因而错误复用节点，产生 `Invalid generated code` 和局部着色异常。现统一为 `THREE.IrradianceNode`。这修复编译与着色正确性，不能把此前全部 GPU 耗时归因于该错误。

公开构建为 `district-B1tsrFsk.js`，完整资源包 **31 文件 / 11,228,105 字节**，没有新增模型或贴图。对照保留 `fused`（上一版光晕算法）与 `static`（本版），两者都包含 Node 入口修复；原 8 通道 `reference` 仍可查看。每种输出图独立缓存，诊断关闭物体阴影采样而不销毁静态阴影缓存。

“优化对照并上报（约 2 分钟）”自动完成夜间六种配置的正反顺序对照：上一版、新版、无光晕、无环境光/反射、无月光阴影采样、仅贴图/烘焙光，共 12 轮各 8 秒。诊断临时改变画面，结束恢复完整效果。每轮保留原始 GPU 间隔、帧间隔及统计；测量 GPU 采样按 250 ms 间隔限频，正常历史仍保留最近 1800 帧。

最终公开版本已通过完整按钮上报与落盘（软件 QA 回执 `0ae019ad`）、逐像素恢复、持续逐帧、中断清除旧结果与恢复控件检查；17 项现有回归通过。软件 GPU 每轮仅 1–4 个 GPU 样本，不作为实机收益或 3 / 5 ms 达标证据。实现、Node 冲突复现、最终图像与 shader 检查记录见 [district-cost-probes.md](../light-study/docs/district-cost-probes.md)。

最终日夜三视角共 12 张截图与五项诊断已核对，fused 与上一版图像一致，新版主要在光晕边缘有很小差异，恢复后像素完全相同。合并脚本之后在巡游阶段遇到浏览器意外关闭，保留了失败记录；新浏览器补测三个巡游姿态通过。检查范围与中断原因未知的边界均记录于 `half-halo-release/validation-summary.json`。
