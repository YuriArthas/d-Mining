# P2 提前实施：稀疏逻辑源与独立地形系统

2026-10-03：用户要求优先做挖坑，P1.5 镐子表现后移。本轮实施地形底座与批量挖除，不把矿物经济、存档或目标手机 60 FPS 标为完成。

## 三层结构

| 层 | 权威/派生内容 | 加载与合并 |
| --- | --- | --- |
| `SparseWorld` | 唯一逻辑源：固定生成版本/种子、坐标规则、稀疏挖除区间 | 不随画面/物理卸载而丢失；未访问或未修改的区域不分配格子数组 |
| `RenderTerrain` | 带矿物颜色的表面 Mesh | 16 格边长仅作为工作范围；同方向同显示类型面贪心合并；54m 加载、78m 卸载 |
| `CollisionTerrain` | Rapier 静态表面碰撞 | 独立 8 格工作范围；只按占据情况合并；12m 近场加载、22m 卸载，额外向下预取 8m |

距离为角色到工作区域 AABB 的轴向范围，实际覆盖包含整个区域，加载/卸载留滞回。加载窗口每移动 4m 重新考虑。两个系统各有 Worker、队列、区域版本、缓存和资源生命周期；共享的只有纯几何合并算法与只读逻辑快照，不把两种结果一起生成或一起驻留。

普通平台、坡道等保留现有普通地形碰撞；本次修改的是可挖矿区。角色与相机继续共用 Rapier，近场准备检查包含角色移动、下落及 7.5m 相机查询范围。

## 稀疏数据规则

- 逻辑范围仍为 100 × 100 × 2000 格，2m 格子。`WORLD_GENERATION` 当前版本 2、种子 0（多矿物外观阶段从版本 1 升级），保留验证场地与矿物分布。
- 16 格边长是修改记录的空间索引，内部只存排序后的删除区间，不存 `16³` 数组或整块位图。
- 第一个孤立删除点占 4 字节区间载荷；连续删除合并成区间；整个索引区删除后归并为全空标记。
- `cell()` 直接查询生成规则和修改记录，渲染和碰撞缓存可以都不存在。未创建碰撞不等于逻辑空气，移动可用性由独立 `ready()` 判断。
- 网格构建直接按坐标采样，复用二维切片掩码，无常驻或临时三维格子/halo 数组。几何缓冲仅保存实际表面。
- Worker 接收受影响范围的快照；快照不改写、不转移走主线程逻辑源。生成结果只含所属系统的网格。
- 当前只做删除。区间在零散棋盘修改下不保证比位图更省；修改载荷按实际修改增长，运行时索引/JS 对象开销另计。刷新后重置，持久化存档仍待实施。

## 挖除与调度

1. 挖除意图去重，等待队列最多 32 格；当前批次最多 8 格，后来的输入等待下一批，避免反复取消导致无法完成。
2. 两个系统分别计算受影响工作区域，仅包含本区和实际触及的面邻区。不同网格尺寸的边界互不绑死；当前无跨角 AO 依赖。
3. 两个 Worker 各自一次最多构建 8 个区域，最多一个在途请求。局部重建优先于该系统的普通预取；没有每格独立 Mesh 或 Collider。
4. 主线程协作式准备预算 2ms/绘制帧，优先近场碰撞；单次 Rapier 创建不可中断，超出预算会被记录，不能宣称硬性小于 2ms。
5. 新碰撞以 disabled 状态准备，新 Mesh 暂不挂入场景。两个系统都完成后，在物理步之前同步提交逻辑、启用新碰撞并切换渲染，随后该物理步刷新 Rapier 查询结构。
6. 区域版本分别维护。某处挖除不使远处无关任务作废；定位改变世界代次并取消未提交挖除，旧 Worker 返回值被丢弃。
7. 等待期间移动会扩展事务需要更新的当前驻留/将加载区域；离开范围的结果不会把远处资源重新挂回来。

`editLatencyMs` 从接受意图算到提交，包含排队；`batchBuildCommitMs` 单独记录该批开始到提交。`renderBuildMs` / `collisionBuildMs` 和各自 `PrepareMs` 分开记录；`terrainMainMs` 覆盖协调、准备和提交。首次 GPU 上传仍包含在整帧渲染测量中，不能用几何对象创建时间代替 GPU 成本。

## 选格修正（2026-10-03）

原实现始终使用相机中心射线，没有读取鼠标指向；命中碰撞三角面后沿射线推进 0.015m 再取整，容易在格子边缘得到邻格。本轮将选格从碰撞网格中独立出来。

- 电脑使用鼠标在场景中的位置，隐藏中心准星，鼠标进入 UI 或离开场景时清除目标。手机继续使用中心准星；混合设备按实际操作切换。CSS 横屏旋转通过逆变换映射到相机坐标。
- 每帧先更新相机矩阵，再按射线做 DDA 网格遍历，直接查询稀疏逻辑源，不扫描全部矿格或渲染三角形，也不创建格子数组。18m 视线、5m 触达距离保持原值。
- 精确落在网格交界时按射线进入方向取格；同时跨过边/角时同时推进对应轴，不把仅擦到零面积边缘的格子当成目标。不使用粘滞或吸附把鼠标附近别的格子改成目标。
- 历史实现（已废止；当前指向射线只用于选格，选中后的空间限制只有 4 格距离，不检查遮挡或渲染驻留）：相机与角色到目标分别检查普通物体遮挡；角色路径再查询逻辑矿块遮挡。角色触到目标的另一面仍算同一格可达，其他格子阻挡则不能开采。附近碰撞未准备好、目标渲染未驻留时不接受选中。
- 高亮和开采共用一个结果。短于一帧的点击保留按下时的瞄准位置，只消费一次；长按继续随当前指向更新。开采间隔保持 0.22s，不增加延迟点击队列。

入口：`src/game/aim.ts`、`GameInput.ts`、`bindInput.ts`、`terrain/raycast.ts`、`terrain/selection.ts`、`validation/ValidationScene.tsx`。`selectionMs` 单独统计选格耗时；鼠标移动不发布 React 状态。

验证：52 项 Node 测试通过，覆盖六面、负坐标、精确边角、边界两侧、稀疏挖除、8/16 格边界、距离与双重遮挡、快速点击和旋转坐标；500 条随机射线另与逐盒相交的独立 oracle 对照。生产类型检查与构建通过。浏览器脚本 `artifacts/check-selection.cjs` 使用世界表面投影定位鼠标，验证离中心指向、实际快速点击只挖高亮格、洞内新暴露墙面、UI 遮挡、普通平台遮挡、超距、旋转相机、旋转窗口和连续六格下挖。手机多指/挖除/方向切换及退出单独回归。

本地选格专项末尾 256 样本中，`selectionMs` P95 约 0.1ms、最大约 2.7ms。仅代表该软件 Chromium 跑法中的 CPU 测量，不是目标手机整帧性能。性能目标按用户最新口径：常态约 16ms/帧，只接受很偶发、且能定位明确原因的卡顿；本轮完成选格正确性，整帧实机门槛与长帧归因仍未验收。

## 手机触点长按（2026-10-03）

- 按下场景立即以触点选格；静止或轻微抖动持续 180ms 后持续挖掘。短点仅预览，不挖除。触点提示圈在进入挖掘时变色，不表示矿块生命或挖掘进度。
- 长按成立前，从最初按下位置移动超过 10 CSS px，进入观察模式；第一段累积位移也交给镜头，后续按增量旋转。观察中停下来不会转成挖掘。
- 进入挖掘后，滑动更新当前触点和选格，不能转镜头；要观察需松手再拖。每次挖空后由当前相机和触点重新查询下一表面，不锁住旧世界坐标。
- 左摇杆、跳跃、场景手势分别持有 pointerId；只有一个场景触点拥有瞄准，额外场景手指不抢占，也不在原手指松开后自动接管。摇杆与跳跃不重置瞄准。
- 松手/取消/丢失捕获清除手势与计时器。捕获中的挖掘触点移到 UI 或场景外会结束手势，不能穿透 UI；尺寸改变、调试定位和退出也清除等待与按住状态。已被地形队列接受的挖除可完成提交，松手后不再发出新请求。
- 移除手机中心准星和独立挥镐按钮，保留跳跃。鼠标继续按指向挖掘、右键观察及短点击锁存；触屏不锁存一次性开采，避免抬起后冒出迟到的点击。

`TouchGesture.ts` 只负责手势状态，`bindInput.ts` 负责唯一计时器、捕获、坐标转换与清理；参数在 `GAME_CONFIG.input`。触点移动不驱动 React 重渲染，不新增 RAF 或全世界格子扫描。常态约 16ms、极偶发长帧需明确归因的目标维持，实机性能仍未验收。

## 多矿物外观与合并验证（2026-10-03）

用户允许跳过主角及动作，本轮仅做矿种外观、分布和合并验证，不接硬度、经济或存档。

- 六种 ID：岩石、深层岩石、煤矿、铜矿、金矿、水晶。除颜色外，分别有碎斑、层理、黑色矿点、铜色斜纹、金色矿粒、青色晶簇；选中时显示矿物名称。
- 普通区域使用固定种子的 3 格尺度成簇分布，深层增加金/水晶占比，深层基岩变为深层岩石。仍由 `baseXYZ` 直接按坐标生成，删除记录来自原稀疏区间，不保存整个矿区或区域格子数组。生成版本升至 2，种子仍为 0；当前尚无持久化存档，不存在旧存档转换。
- 一张代码生成的 192×32 RGBA 图集，CPU 原始载荷 24 KiB，六个 32×32 图块。所有普通矿区 Mesh 共用一个表面材质；矿物变化不创建单独材质组或每格 Mesh。
- 合并键仍是矿种 ID 与朝向；不同矿种不合并外露面，相邻实心格之间不生成内面。每个顶点的 UV 以格为单位，图集采样逐格重复，长条/整片合并面不会拉伸纹理。UV + 矿种索引合计 3 个 float，替代原 RGB 的 3 个 float，单顶点载荷不增加。
- 碰撞输出只看占据，不发送 UV/矿种属性，也不依赖图集或渲染缓存；8 格碰撞与 16 格渲染的独立队列和驻留规则不变。

固定矿样位于 `z=-32..-17`、`y=-16..-1` 的逻辑格范围，三组沿 x 相邻。它们与普通地形走同一条逻辑采样、Worker、合并、碰撞与挖除路径，不是单独绘制的展示模型。

| --- | --- | ---: | ---: |
| 整片岩石 | -16..-1 | 2 | 8 |
| 六种连续条带 | 0..15 | 12 | 8 |
| 六种逐格交错 | 16..31 | 512 | 8 |

渲染按一个 16 格区域统计；碰撞按覆盖同面积的四个 8 格区域合计。空白“—”表示相应缓存未完整驻留，不能解释为零个面。挖除后形状改变，渲染与碰撞三角形数都会合理增加；只有材料变化时碰撞几何保持相同。
