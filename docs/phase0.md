## P0.1：最小工程与独立构建

- 版本与相邻工程对齐，用本项目锁文件锁定；固定 Node 24.x。
- HTML 入口、React 挂载和一个空 R3F Canvas，清楚显示“游戏准备中”。
- `base: './'`，资源随静态产物交付，不在运行时加载外部 CDN。
- 本地静态服务器使用 4175；开发服务器与实际交付入口分开。
- 验证根目录运行、子目录运行、资源状态码和浏览器运行时错误。

不把空 Canvas 的低负载当作 60 FPS 验收，也不提前实现角色、矿坑或框架。

## P0.3：横屏与基础布局

- 电脑与手机始终使用横屏布局；竖向窗口内将整屏顺时针旋转 90°，不显示旋转提示。
- 手机浏览器地址栏和安全区域变化时，内容不溢出或被遮挡。
- 不把浏览器强制全屏/锁横屏作为运行前提。
- 横向窗口直接铺满，竖向窗口交换游戏宽高并旋转；画布按旋转前尺寸渲染，摇杆/镜头使用游戏坐标，安全区域同步映射。切换方向时结束旧手势，避免沿用失效坐标。
- 浏览器尺寸模拟检查与真机检查分开记录。

## P0.4：退出

用户最新决定：删除暂停、继续、重开和专门的后台处理，只保留退出。

- 横屏和竖屏均提供“退出游戏”按钮。
- 退出时停止本游戏的更新，释放监听器、渲染资源及后续实际引入的其他资源。
- 使用 R3F 的卸载完成回调，待事件解绑、场景和 renderer 释放后再跳转游戏列表；独立部署无列表时，同页移除 Canvas 并显示“已退出游戏”。
- 退出跳转使用 replace，避免浏览器后退恢复已销毁的空场景；重复点击不会触发多次退出。
- 在场景尚未初始化完成时退出，通过 Canvas 自身卸载处理未完成初始化。
- 本项目不增加暂停菜单、恢复确认、重新开始或清空进度按钮，也不建立切后台状态流程。

验收：退出后原游戏不再运行，多次进入/退出没有重复监听或资源累积。
